# 全屏 Book Reader：沉浸式翻阅（2026-11-11 · 设计，等待确认；未改 App 代码）

设计稿两张（真实 App 上运行时注入的原型，书页是 App 自己渲染的真实页面；数据是合成示例；Chromium 模拟 iPhone，不是真机）：

- 「流程」：现在的书本详情（翻页区在约 760px 之后）→ 新的详情页「开始翻阅」→ 阅读器封面 → 内页 → 点「编辑」进入 Journal Studio → 回到原位置；「继续翻阅」变体；新的详情页整页。
- 「状态与控件」：封面、内页（控件显示 / 隐藏）、滑动中间帧、页面缩略图、视频与声音、更多、长文字与「阅读全文」、示例页；375×667、430×932、English。

目标：打开一本手帐时，是翻开一本小书，而不是往下滚一个长网页。只改「怎么读」，不改书、页面和媒体的数据。

## 1. 现状（代码核实，提交 4cb71ce）

- **书本详情** `booksPage()`（`Public/app.js`，`selectedBook` 分支）：返回 / 编辑 → 封面 `.book-detail-showcase` → 书名、简介、标签、「私人 · N 篇」→（实验室）共同创作 → 「记录新的一页」`book-new-entry` → 「分享给家人看（PDF）」`book-share` + 说明 → 背景音乐 `bookMusicHTML()` → 「列表 / 翻页」切换 `.book-view-switch`（`book-view`，记在 `little-days.book-view`）→ 列表（月份 / 日期筛选 + `dayCoverHTML`）或内嵌翻页 `flipBookHTML()`。
- **内嵌翻页** `flipBookHTML(book)`：阅读序列 = 封面 + `flipPages(bookId)`；`flipPages` 就是 `bookSharePages(state, bookId, { includeDemo: true })`（`js/book-share.mjs`）——按日期从早到晚，每天先是「当日主页」（属于这本书且有内容时），再是这天属于这本书的各页；只有草稿的日子也算。状态是模块变量 `flipIndex`（0 = 封面）、`flipTurn`、`flipBookId`；页码文案 `journey.pageOf`「第 9 / 9 页」把封面也数进去。
- 一页的内容：`.flip-head`（日期 · 时间、示例标记、音乐片）→ 标题（仅当标题不在纸面上时）→ `.flip-canvas` 里的 `sharedCanvasHTML(page, ctx(), { readOnly: true, dayPage: !moment })`（即 `js/canvas.mjs` 的 `canvasHTML`，Studio、当天页、导出共用）→ 当天清单 `.flip-checklist`（每天第一页）→ 「编辑这一页」`read-edit` + 「打开这一天」`open-day` → 「听听 Captain 怎么说」`keeperAskHTML()`。
- 翻页：`turnPage(dir)` + `render()`；文档级 `pointerdown` / `pointerup`（横向 > 50px 且 > 纵向 1.4 倍）；方向键；CSS `page-turn-next / prev`（0.5s 的 3D 翻转，`prefers-reduced-motion` 下不播）。
- **实测位置**：393×852、实验室关闭、书有背景音乐时，详情页整页 1397px，翻页区从第 760px 才开始——首屏完全看不到书页。
- **媒体在翻页里放不了**：音视频文件按视图 scope 载入，`releaseLeftScope()` 只认 `["studio", "day"]`。书本页不是这两个 scope，所以翻页里视频 / 声音一直显示「正在从本机载入…」，没有播放按钮；要点「打开这一天」才能播。图片是 app 级常驻，不受影响。
- **长文字被截断**：纯文字页（`.journal-canvas.text-only`）正文 `max-height: 46%; overflow: hidden`，超出 4:5 纸面的文字在只读视图里看不到（翻页、当天页都一样），也没有提示。
- **书页比例**：`.journal-canvas` 固定 `aspect-ratio: 4/5`，内部用 `cqw` 单位，放大缩小不变形。封面 `.book-cover` 是固定像素尺寸（详情页 190×255）。
- **从阅读处编辑**：`read-edit` → `openStudio(date)` + `selectMoment(id)`，并记 `readReturn = { page, book, date, moment }`；完成或返回时 `returnToReading()` 恢复 `page` / `selectedBook`，`flipIndex` 没动，所以回到同一页。保存新页后的 `showSavedPage()`、快速记录完成后也是「打开这本书的翻页，翻到那一页」。
- **背景音乐** `syncMusic()`：进入书本详情就播这本书的音乐；翻页中某页有自己的音乐则换成那一首，没有则继续放；`musicPaused` 记住用户按了暂停。
- **隐藏底部导航**：Studio 用 `#phone.in-studio`（`render()` 里 `classList.toggle`）+ CSS `.phone.in-studio .bottom-nav { display: none }`。
- 翻页里点照片会放大（`zoom-photo` → `openLightbox`）。
- 数据侧没有「阅读进度」字段；Swift 模型 `JournalBook` 也没有。

## 2. 方案总览

1. 书本详情页不再内嵌翻页区；增加主要入口「开始翻阅 / Read Book」，点封面也进入。读过之后变成「继续翻阅 · 第 N 页」，旁边「从封面开始」。
2. 新增独立的全屏阅读器：隐藏底部导航；一屏一个阅读位置（封面 + 每一页）；左右滑动 / 轻点两侧翻页；轻点中间显示 / 隐藏控件。
3. 列表保留在详情页，作为页面导航：点某一天直接进阅读器并翻到那天的第一页。
4. 阅读器里点「编辑」进入这一页的 Journal Studio，完成后回到同一位置。
5. 阅读器是书页上音视频的播放场所（按需载入、不自动播放）；背景音乐规则不变，多一个一键静音。

不重新做数据结构：阅读序列继续用 `bookSharePages()`，书页继续用 `canvasHTML(..., { readOnly: true })`。

## 3. 书本详情页（入口）

从上到下：返回 / 编辑 → 封面（可点，进入阅读器）→ 书名、简介、标签、「私人 · N 篇」→ **「开始翻阅」主按钮**（52px 高，书本图标）+ 一行小字「封面 + 8 页 · 点封面也可以翻开」→ 一行两个次按钮「记录新的一页」「分享给家人看（PDF）」+ PDF 说明 → 背景音乐 →「页面列表」（标题右侧「点一天，直接翻到那里」）+ 月份 / 日期筛选 + 每天的卡片。

- 读过这本书后：主按钮「继续翻阅 · 第 5 页」，小字「上次看到「下午的咖啡好治愈」」+ 文字链接「从封面开始」。
- 书是空的：主按钮仍可点，进入只有封面的阅读器，封面下写「这本书还没有页面」；详情页保留「记录新的一页」。
- 移除：「列表 / 翻页」切换、内嵌翻页区、底部「左右滑动或点 ‹ ›…」提示。`little-days.book-view` 不再读取（旧值留着不删）。
- 实测（原型）：详情页整页 1397px → 1422px（列表全部可见），「开始翻阅」在 393×852 和 375×667 的首屏内。
- 「记录新的一页」从主按钮降为次按钮——这是一处优先级变化，见第 11 节问题 2。

## 4. 全屏阅读器

### 4.1 版面

- 一个盖住整个 App 区域的页面（状态栏以下到屏幕底），底部导航隐藏。底色是比纸略深的暖亚麻色（中心稍亮），书页是纸白色、发丝线 + 柔和落影，像放在桌面上的一页。跟随主题色，不做深色影院模式。
- 书页保持 4:5，不裁切、不拉伸：宽度 = min(屏宽 − 28px, 可用高度 × 0.8)。实测：375×667 → 328×410；393×852 → 365×456；430×932 → 402×503。
- 书页下方两行说明（不在纸面上）：日期 · 时间（12px）、标题（17px/600，仅当标题不在纸面上时，与现在的规则相同）；示例页带「示例」小标签，草稿带「草稿」小标签（状态规则见第 7 节）。
- 封面位置：封面放大到约 247×332（小屏 190×255），下面是书名、简介、「2026年10月30日 – 2026年11月11日 · 8 页」和「向左滑动翻开 ›」。

### 4.2 顶部控件（56px，浮在桌面上，可隐藏）

`‹` 返回书本详情（44px 圆形纸片）· 中间小字 MY BOOK + 书名（过长省略）·「✎ 编辑」（胶囊，鼠尾草绿文字）·「⋯」更多。

- 封面位置上「编辑」变成「编辑书本」（打开现有的书本编辑）。示例页没有编辑按钮（与现在相同）。
- 更多（Bottom Sheet）：打开这一天（现有的当天页）· 这一天的清单（原 `.flip-checklist`）· 背景音乐 · 回到封面。「听听 Captain 怎么说」也放在这里（Keeper 开启且不是示例页时）。

### 4.3 底部控件（可隐藏）

左：页面缩略图入口（四格图标）· 中：`‹  第 5 页 / 共 8 页  ›` 胶囊（两端按钮 44px，第一页 / 最后一页时变淡禁用）· 右：音乐开关（有背景音乐时显示；播放中是鼠尾草绿实心，静音是带斜线的描边）。

最底下一条 3px 的进度线：每个阅读位置一段，封面那一段短一些；控件隐藏时仍然保留，是唯一留下的界面元素。

### 4.4 页码写法（建议）

- 阅读位置 = 封面 + N 张内页（例：封面 + 8 页 = 9 个位置）。
- 建议显示：在封面上写「**封面** · 共 8 页」；在内页上写「**第 5 页** · 共 8 页」。也就是**封面不占页码**，内页从 1 数起。理由：App 里其他地方（「N 篇」、PDF、当天页的页码）数的都是内页，这样「第 5 页」到处是同一页；进度线负责表达「封面也是一个位置」。
- 备选：全部按位置数——「封面 · 1 / 9」「6 / 9」（现在的内嵌翻页就是这样）。见第 11 节问题 1。

### 4.5 页面缩略图（Bottom Sheet）

三列网格：封面 + 每一页的小图（就是同一份书页渲染缩小，`cqw` 自动适配）、页码 + 日期、草稿 / 示例小标签、有音视频的页右下角一个小 ▶；当前页有鼠尾草绿外环。点一页 → 关闭面板并直接翻到那里。实现时小图按需渲染（滚到才画），避免一次画几十页。

### 4.6 长文字

书页本身保持原样（不改纸面排版，不在纸上滚动）。检测到正文被截断时，书页下方出现「阅读全文 ›」，点开一个只读面板显示这一页的完整标题和正文（可选中复制）。这同时解决了第 1 节里「超出的文字现在看不到」的问题，而不动原始数据和纸面。

## 5. 翻页动画与手势

- **滑动**：手指横向拖动时书页跟手平移，相邻页从旁边进来（两页之间留一点桌面）。松手：位移 > 屏宽的 18% 或快速一甩 → 翻页，否则弹回。过渡 320ms、ease-out；不做 3D 翻书、不做回弹夸张效果。第一位置 / 最后位置继续拖有阻尼、不翻。
- **轻点**：屏幕左 20% / 右 20% → 上一页 / 下一页；中间 60% → 显示 / 隐藏上下控件（180ms 淡入淡出，书页位置不动）。
- **键盘 / 辅助**：方向键左右翻页（已有）；上下控件按钮都有 `aria-label`；页码变化用 `aria-live="polite"` 读出。
- **Reduce Motion**：`prefers-reduced-motion: reduce` 时不平移，改为 150ms 淡入淡出（或直接切换）；控件显隐不带位移。
- **与页面内操作的冲突**（阅读器里书页是只读的，没有拖动图层）：
  - 判定方向：按下后移动超过 10px 才判定；横向分量 > 纵向 1.4 倍 → 翻页手势并接管；否则放弃（不翻页）。
  - 播放按钮、视频、声音票据：点击永远交给它们，不翻页、不切换控件；在这些元素上起手的横向拖动仍然可以翻页（按位移判定，不靠是否点中）。
  - 照片：现在「点照片放大」会和「点一下显示 / 隐藏控件、点两侧翻页」冲突。建议阅读器里**单击不放大**，改为**双击照片放大**（仍用现有的 Lightbox）。见第 11 节问题 3。
  - 底部面板（缩略图 / 更多 / 阅读全文）打开时，底下的书页不响应滑动。
  - 屏幕左缘的系统返回手势（iOS 外壳 WKWebView）：阅读器不拦截；左缘 16px 内起手的拖动不触发翻页，避免两者打架。未在真机验证。
- **第一阶段不做**：双指缩放书页、长按菜单、自动翻页、横屏排版。

## 6. 媒体与背景音乐

- 视频 / 声音：阅读器成为一个媒体 scope（与 `studio`、`day` 并列），只为**当前页和相邻页**载入文件；翻走即暂停，离开阅读器即释放。页上显示现有的播放按钮（`layer-play`），**不自动播放**。视频点播放后在原位播放；声音是现有的票据样式。
- 背景音乐：规则与现在相同（书的音乐；某页有自己的就换，没有就继续），尊重用户在别处按过的暂停（`musicPaused`）。阅读器右下角一个开关，一点即静音 / 恢复；页上的视频或声音开始播放时，背景音乐自动压低或暂停，播完恢复（建议暂停，逻辑最简单）。
- 浏览器的自动播放限制不变：没有用户手势时背景音乐可能不会自己响，开关显示真实状态。
- PDF 分享只在书本详情页，阅读器里没有导出入口。

## 7. 与数据结构、Journal Studio 的整合

- **阅读序列**：`bookSharePages(state, bookId, { includeDemo: true })`，封面是位置 0。不新增数据结构；`flipIndex` / `turnPage()` / 滑动与方向键监听可以直接搬进阅读器。
- **状态**：建议保持 `page === "books"` + `selectedBook`，新增一个模块状态 `reading = { book, key }`（`key` = `日期|页面 id`，封面为 `cover`）。`render()` 里 `#phone.classList.toggle("in-reader", …)`，CSS 复用 `.in-studio` 隐藏底部导航的写法。这样 `readReturn`、`navigate()`、音乐上下文 `book:<id>` 都不用改语义。
- **按页面身份而不是序号定位**：进入、返回、恢复进度都用 `日期 + 页面 id` 在当前序列里找位置；找不到（页面被删、移到别的书）就落在最近的一页或封面。这样编辑时增删页面不会回错位置。
- **阅读进度**：`localStorage` 键 `little-days.reader-pos` = `{ [bookId]: { date, moment, at } }`，只在这台设备，是偏好不是手帐内容——不进 `little-days.v1`、不进备份、不需要改 Swift 模型。将来原生端用 `UserDefaults` 存同样的三项即可，含义一致。
- **列表 → 阅读器**：详情页列表里 `dayCoverHTML` 的点击改为「进入阅读器并翻到这天的第一页」。当天页（Day Detail）不删除：日历、首页、搜索仍然打开它；阅读器「更多 → 打开这一天」也能去。
- **保存后**：`showSavedPage()` 和快速记录完成后，改为进入阅读器并停在刚保存的那一页（现在是内嵌翻页的那一页）；`‹` 回到书本详情。
- **编辑 → 回到原处**：沿用 `read-edit` + `readReturn` + `returnToReading()`；`readReturn` 多带一个 `reader: true` 和页面身份，返回时重新打开阅读器到那一页，书页用最新数据重画。图层、文字格式、照片布局不经过阅读器，不会被改动。
- **草稿 / 完成**：阅读器只读取记录状态，不定义它。主会话正在给记录加可选的 `status: "draft"`（Journal Studio 退出与草稿那一项）；阅读器和缩略图对草稿页显示低调的「草稿」标签，其余照常可读可编辑；只有草稿的日子现在就已包含在 `bookSharePages()` 里。具体规则以那一项的实现为准。
- **Web 与 SwiftUI**：iOS 外壳加载同一份页面，阅读器不需要另写原生界面；安全区用 `env(safe-area-inset-*)` 留出刘海和底部横条。

## 8. 留在详情页的 / 不改的

- 留在书本详情页：编辑书本、记录新的一页、分享 PDF（及说明）、背景音乐选择、页面列表与筛选、（实验室）共同创作。
- 不改：My Books 书架和品牌视觉、封面模板、书和页面的数据、媒体存储、PDF 生成、当天页、日历、Journal Studio 本身、背景音乐曲库。
- 不做：新的静态截图式阅读、另一套页面数据、3D 翻书。

3. 缩略图面板、更多面板、阅读全文。
4. 媒体 scope（当前页 ± 1）、音乐开关。

6. 测试、文档、发布。

## 10. 如实说明

- 没有改动仓库里的 App 代码；在线链接没有变化；没有跑回归。
- 设计稿是在提交 4cb71ce 的真实 App 上运行时注入样式和脚本得到的：书页、封面、Studio、详情页都是 App 自己渲染的；阅读器的外框、控件、面板是原型代码，页码、「继续翻阅 · 第 5 页」「上次看到…」等文字是原型里写的。
- 原型里的视频页借用了当天页已载入的媒体来显示封面帧和播放按钮；「翻页里现在放不了视频」是现状，阅读器里要按第 6 节实现后才成立。
- 滑动的阈值、时长是建议值。原型里验证过：点右侧 / 左侧翻页、点中间显示 / 隐藏控件、横向拖动翻页、纵向拖动不翻页、‹ › 按钮、缩略图跳转都能用；有一个已知的原型缺陷——横向拖动结束时会多触发一次控件显隐，实现时要屏蔽。没有做手感调校，也没有在真机上试过。

- 很多页（几十页以上）时的性能没有测；方案里用「只画当前页和相邻页、缩略图按需画」来控制。

## 11. 需要你确认

1. **页码写法**：封面不占页码——「封面 · 共 8 页」「第 5 页 · 共 8 页」（建议）；还是按位置数「封面 · 1 / 9」「6 / 9」？
