## 2. 设计

结构不变：Captain's Corner 仍然是「聊天 / 玩耍 / 装扮」三个标签。进入「玩耍」后：
- 面板自动展开到最高（375×667 上也放得下整个舞台和按钮）；
- 页面上不再出现开发说明。

**主体是一个大舞台**：
- 一张方形的奶油色纸卡，宽度等于面板宽减 32px，393 宽时约 361px。圆角 28px，轻投影。
- Captain 占满舞台（素材本身就带奶油色背景，舞台就是图本身，没有接缝）。
- 左上角一个气泡邀请，例如「陪我玩毛线球嘛！」。
- 第一次进来时，毛线球上有一个手指和「拖一拖毛线球」的提示，玩过一次就不再出现（只记在这台设备上）。

**舞台下方**：
- 一行很轻的提示（播完后换成 Captain 的一句话，例如「抓到啦！再来一次？」）；
- 三个圆角大按钮（高 78px）：
  - **玩毛线球**：可以玩，深绿色；
  - **摸摸头**、**挠肚皮**：没有素材，显示为浅色描边，下面一行小字「还在画」，点不了，也不占主要区域。

**状态**：

| 状态 | 表现 |
|---|---|
| Idle | 静态坐姿，气泡邀请 |
| 播放中 | 播两遍玩毛线球动画；按钮变淡不可点，防止重复触发；没有声音 |
| 播完 | 停在最后一帧（抱住毛线球），显示一句话；约 3 秒后淡回 Idle |
| 减少动态效果 | 不播动画，直接显示关键帧（拨球、爱心那一帧）和那句话 |
| 无帽装扮 | 显示无帽的静态图，说明「这套装扮的玩耍动画还在画」，一个按钮「换上柠檬帽一起玩」，三个按钮都不可点 |

**装扮联动**：
- 舞台只显示与当前装扮一致的素材，玩到一半不会从无帽变成柠檬帽，反过来也一样。
- 柠檬帽缺少的动作就不开放。
- 绿领巾的问题见第 5 节第 1 问。

**手感**：
- 舞台和按钮都不会关闭面板：面板的下拉关闭只在顶部把手和标题区生效，舞台上的拖动交给毛线球。
- 原生端开始播放时给一下轻触觉反馈（见第 4 节）；网页端没有。

## 3. 三个玩法的操作流程

**玩毛线球（现在就能做）**
1. 进入 Playroom，看到 Captain 坐在毛线球旁，气泡写着「陪我玩毛线球嘛！」，毛线球上有手指提示。
2. 两种开始方式：
   - 按住毛线球往 Captain 那边拖，松手；
   - 或者点「玩毛线球」按钮。
3. Captain 伸爪拨球，冒出小爱心，最后抱住毛线球，播两遍。
4. 停在抱住的样子，显示「抓到啦！再来一次？」，3 秒后回到 Idle。
5. 播放过程中再点再拖都不会重新开始；播完才能再玩。

**MVP 与最终版的差别（如实说明）**：
- 现在的拖动只是「开始播放」的手势，毛线球本身不跟手移动。
- Captain 的视线也不会跟着球走。要做到跟手和跟视线，需要可以拆分的分层素材，或者「看左 / 看右 / 扑」几段短动画。

**摸摸头（等素材）**
- 最终版：轻点或轻轻划过 Captain 的头 → 开心、眯眼、蹭手的动画 → 回到 Idle。
- 需要的素材：Pet 动画，至少「眯眼」和「蹭头」两段，柠檬帽和无帽各一套。
- 实现方式：在素材数据里给每帧标出头部区域（按百分比），点在这个区域里就触发。
- 素材到位之前，按钮显示「还在画」。

**挠肚皮（等素材）**
- 最终版：点「挠肚皮」→ Captain 躺下露出肚皮（过渡动画）→ 用户在肚皮上来回划 → 扭动、笑、挥爪 → 翻身回到坐姿。
- 需要的素材：躺下、肚皮反应（可循环）、起身，三段，两套装扮。
- 素材到位之前，按钮显示「还在画」。

## 4. 实现方案

**网页端（现在的 App 界面，iPhone App 外壳加载同一套页面）**：
- 素材：`tools/make_captain_anim.py` 把原始 GIF 的每一帧原样（不抠图、不重画）排成一张 JPEG 雪碧图，放在 `Resources/Keepers/`。目前生成了 `LD-keeper-cat-lemon-sit.jpg`（26KB）、`-hug-anim.jpg`（136KB）、`-play-anim.jpg`（199KB）。
- 确认后：在 `library.json` 的 `keepers` 里登记 `mood: "stage-*"`、`frames`、`frameMs`、`still`；`keeperAsset()` 跳过 `stage-*`，不把这些图当成普通 Captain 图；新增 `keeperStage()` 读取这些素材。现在这些都还没有改，App 目前只是多带了三张没被引用的图（共 361KB）。
- 曾经试过逐帧抠成透明 PNG：256 色的 GIF 抠完后，浅色爪子上有小缺口，深色背景上还留着一圈地面边，达不到要求，已放弃。
- 播放：CSS `steps(n, jump-none)` 驱动雪碧图，`animationend` 后回到 Idle；`prefers-reduced-motion` 时只显示关键帧。
- 拖动：在毛线球区域用 Pointer Events。开始拖动 → 显示小提示 → 松手触发播放。舞台设 `touch-action:none`，不会触发面板下拉。
- 以后的头部、肚皮触摸区：在素材数据里给每帧写区域，点击时做命中判断。

**原生端（Swift 外壳）**：
- 触觉反馈：页面通过一个 `WKScriptMessageHandler`（例如 `littleDaysHaptics`）告诉外壳，外壳调用 `UIImpactFeedbackGenerator(.light)`。
- 需要改 `LittleDaysWebShellView.swift`。这个文件目前有你 Mac 上另一个会话的未提交修改，所以等那批修改提交后再加。
- 网页端没有触觉反馈，不影响使用。

**未来如果做全原生的 Playroom（现在不建议）**：
- 按照架构约定，界面只维护 `Public/` 一份。真要做原生 SwiftUI 版，可以用 `TimelineView` 播放雪碧图，用 `DragGesture` 拖毛线球，用 `.sensoryFeedback` 做触觉反馈；或者交付 Lottie 素材后接入 lottie-ios。
- 这会多出一套要维护的界面，要单独决定。

**不做**：签到、金币、饥饿值、养成；不新增 Bunny、Westie 等其他 Keeper；不默认播放声音。不影响聊天和本地 Qwen 实验，也不影响手帐、日历、书架和 Journal Studio。
