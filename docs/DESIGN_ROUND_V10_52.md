## 一、页面管理与排序（阅读器 ···、书架 ···、日历「目录」共用一套）

### 1. 现状（查过代码）

| 位置 | 现在能做什么 | 问题 |
|---|---|---|
| 阅读器右上角 ··· | 打开这一天、这本书的音乐、回到封面、隐藏 / 显示封面、Captain | 想删除、调顺序的人会先点这里，但这里没有 |
| Journal Studio 页面目录（标题下拉） | 同一天的页面 ↑↓、复制、删除、封面行（V10.47 起只在有封面时显示） | 要先进编辑器；只能管一天 |
| 日历单日 | 统计卡 + 完整目录 + 完整内容 | 目录和内容重复（见第二节） |
| 书本顺序 | `pages.mjs visiblePages` 按日期排，同一天内按 `entry.moments` 数组顺序 | 整本书不能自定义顺序 |

阅读器、书本详情、PDF、书本页数统计都用同一个 `visiblePages`；日历也用它，但不传书本。所以**排序只需要改一处，按书生效**，日历自然保持真实日期。

### 2. 推荐的信息架构

- **一个「页面管理」界面，三个入口**：
  - 阅读器 ··· →「管理页面」（菜单第一组）。
  - 书架卡片 ··· →「管理页面与顺序」。
  - 日历单日顶部「目录」。
  - 日历进入时只显示那一天的页面，书本进入时显示整本书的页面。
- **阅读器 ··· 重新分组**（不变长）：
  - 第一组：管理页面 · 打开这一天。
  - 第二组：这本书的音乐 · 回到封面 · 隐藏 / 显示封面。
  - 最后一组：Captain。
  - **建议把 Captain 从这里移走**：阅读时的菜单应该只放和这本书有关的操作。Captain 已经在首页和设置里，留在这里只会让「我找不到删除」更难找。

### 3. Bottom Sheet 还是全屏？推荐：**全屏（从底部推入）**

| | Bottom Sheet | 全屏 |
|---|---|---|
| 缩略图网格 | 只能看到 4–6 张，拖动时一边滚动一边拖，很容易拖错 | 3 列网格，一屏 9–12 张 |
| 拖动排序 | 和 Sheet 的下拉关闭手势冲突 | 没有冲突 |
| 「完成 / 取消」 | 容易被当成「关掉就算了」 | 顶部明确的「取消」「完成」，改动在「完成」时一次保存 |
| 与 Capiday 风格 | 轻 | 纸张底色、细线、衬线标题，像在翻手帐的目录页 |

日历单日「目录」只是**看和跳转**，用 Bottom Sheet；要整理时，Sheet 里的「整理」再进入全屏管理。

### 4. 全屏页面管理（设计预览第 1 块画板）

- **顶部**：取消 · 《书名》· 完成。
- **排序方式**（分段控件）：日期正序 · 日期倒序 · 自定义。
  - 在日期排序下长按拖动 → 自动切到「自定义」，并在顶部提示一次。
- **3 列缩略图网格**：
  - 每张写页码、日期、标题（可以为空），以及类型小图标（照片 / 文字 / 声音 / 手绘）。
  - 可选封面单独一行，标「封面（可选）」，可以隐藏或删除。
  - 封面固定在第一位，不参与排序。
- **长按拖动**：被拖的卡片抬起，其余卡片让位；拖到边缘自动滚动。
  - 每张卡片还有「↑ ↓」按钮（无障碍和不方便拖动时用）。
- **选择模式**：「选择」→ 勾选 → 底部「删除（N）」，先确认。
  - 删到书里一页都不剩：沿用 V10.47 的「清空这一天 / 可恢复」规则，不会留下删不掉的空封面。
- **点缩略图**：打开那一页的阅读视图；卡片上的 ✎ 进入编辑。
- **完成**：写入顺序，阅读器立刻按新顺序显示。**取消**：什么都不改。

### 5. 排序数据模型（最小改动，可选字段，不迁移）

```jsonc
// book（书本）
{ "pageOrder": "date" | "date-desc" | "custom",   // 缺省 = "date"（旧书的行为）
  "customOrder": ["2026-11-13|m-abc", "2026-11-10|m-def", ...] }  // Reader.keyOf：日期|页面 id
```

- 只改**显示顺序**：页面的日期、照片拍摄时间、`entry.moments` 里的内容都不变。
- `visiblePages(state, { bookId })` 按 `pageOrder` 排序。
  - `custom` 时按 `customOrder` 排；不在列表里的新页面按日期插在最后（**新增页面不会打乱已有顺序**）；列表里已经不存在的 key 直接忽略。
  - 切回「日期」时 `customOrder` 保留，以后还能切回去。
- **同一天内的顺序**仍然是 `entry.moments` 的数组顺序（已经能调），日历单日也按这个顺序。
  - 按时间排序是**一个动作**（把这一天的页面按 `time` 排一次），不是一种模式，避免两种状态互相打架。
- 日历：按真实日期，不受书本顺序影响。
- PDF / 页数 / 页码：都来自 `visiblePages`，自动一致。
- 备份：book 上多两个可选字段，旧版本读取时会忽略。
- Swift `Models.swift`：book 加两个可选字段，并补 Core 测试。

### 6. 风险

- 页面的 key 依赖「日期 + 页面 id」：把页面移到别的日期后，它在自定义顺序里的位置会丢失（回到末尾）。实施时，移动日期要同步更新 `customOrder`。
- 删除书本：只允许删空书（V10.51 已经这样做）。

### 7. 分阶段

1. **P1-a**：阅读器 ··· 重新分组，加「管理页面」→ 全屏管理界面（网格、选择删除、打开、编辑），排序方式只有日期。
2. **P1-b**：`pageOrder` / `customOrder`，长按拖动和 ↑↓，「完成」写入。
3. **P1-c**：书架 ··· 和日历「目录」接到同一个界面。

**测试用例**：
- 旧书默认按日期，显示与现在逐字节一致。
- 自定义顺序后：重新打开、阅读器、PDF 的顺序一致；日历不变。
- 新增页面不打乱已有顺序。
- 切回日期再切回自定义，顺序还在。
- 删除最后一页沿用 V10.47 规则。
- 备份恢复后顺序还在；Swift 解码有 / 没有新字段都能读。

### 8. Challenge

- 你提的「同一天：自动按时间 / 自定义拖动」两种模式，我建议**只保留拖动，加一个「按时间排一次」按钮**。两种模式会让人困惑：哪个才算数？拖完以后又怎样？
- 合并 / 拆分照片到不同页面，属于 P1 照片分组方案（`docs/PHOTO_GROUPING_PLAN.md`），不放进页面管理，免得这个界面变成文件管理器。

## 二、日历单日：阅读优先，整理按需

### 1. 现状问题

点开一天后依次是：
1. 统计卡（4 页 · 6 张照片 · 1 段声音）；
2. 完整目录；
3. 同样 4 页的完整内容。

看到内容之前要先经过两层「管理信息」。

### 2. 新结构（设计预览第 2 块画板）

```
2026年11月13日 · 星期五                [目录]  [编辑]
这一天的故事
4 页 · 6 张照片 · 1 段声音
──────────────
第 1 页（原样渲染，标题、时间、书名小标签、··· ）
（留白 28px + 一条细线）
第 2 页 …
```

- 统计改成标题下一行小字，不再用卡片。
- **「目录」打开 Bottom Sheet**：
  - 每行：缩略图 · 01 · 18:47 · 2 张照片 · 书名。
  - 点一行跳到那一页；底部「整理这一天」进入全屏页面管理（第一节）。
- **页面所属的书**：同一天的页面属于不同的书时，每页标题旁有书名小标签。
- **只有一页**：不显示「目录」按钮。

| 特殊情况 | 处理 |
|---|---|
| 没有记录 | 一行小字 +「记一页」 |
| 只有文字 | 缩略图用文字纸样，不依赖照片 |
| 只有语音 | 显示播放器和标题 |
| 有手绘 | 照常显示 |
| 旧版每日封面 | 显示中的封面算第 1 页；隐藏的封面不显示 |
| 草稿 | 保留「草稿」标签，浏览不会把它标成完成 |
| 删除最后一页 | 沿用 V10.47 规则 |

### 3. 改动范围

- 只改日历单日的渲染（`dayDetailHTML` 一带）和新的目录 Sheet，**不改数据**。
- 测试：
  - 4 页的一天，第一屏就能看到第 1 页的内容（截图对比 375 / 430）。
  - 目录跳转、整理入口、只有一页、没有记录。
  - 跨书的书名标签；草稿状态不变。

## 三、新手引导

### 1. 首次打开为什么没有引导（已查到根因）

`Public/app.js` 启动时：

```js
// Without Labs there is no sign-in page or tour: open straight onto Home.
if (!labsOn() && !Account.isSignedIn(account)) {
  Account.signIn(localStorage, {});
  account = Account.finishTour(localStorage);   // ← 直接标记为「看过了」
}
```

实验功能默认是关的，所以每个新用户在第一次启动时就被标记为「已完成引导」，7 页的介绍从来不会自动出现，只能从「设置 → 功能介绍」进入。

Studio 里的四步教程有自己的判断：「没有自己的页面才自动开始」。这个判断是对的，但只在第一次进入编辑器时出现。

### 2. 推荐流程（比你的 6 步更短）

我建议**首页只用 3 步**，其余的「等用到的时候再说」：

| 步 | 高亮 | Captain（中文 / English） |
|---|---|---|
| 0 欢迎（小卡片，不遮首页） | — | 「嗨！我是 Captain。带你认识一下开铺手帐吧？」 / "Hi, I'm Captain. Want a quick look around?" ［带我看看］［我自己探索］ |
| 1 | 「选今天的照片」大卡片 | 「选几张喜欢的照片，就能排成漂亮的一页。」 / "Pick a few photos and they become a page." |
| 2 | 「只写几句 · 手绘 · 更多方式」整排 | 「没有照片也行：写一句、画几笔、录一段声音都可以。」 / "No photos? Write a line, draw, or record a sound." |
| 3 | 底部「日历」+「书架」 | 「记下的每一天都在日历里，也收在你的手帐本里。」 / "Every day lands in your calendar and your books." |
| 4 邀请 | — | 「要不要现在做你的第一页？」［开始我的第一篇］［以后再说］ |

- 「开始我的第一篇」直接打开现有的「今天怎么记」面板，不另做编辑器。
- 第一次进入编辑器时，沿用已有的四步 Studio 教程（只讲：加照片 / 文字 · 换排版 · 自由移动 · 完成）。
- **Captain 只在第 0 步和第 4 步露脸**，中间 3 步只有一个小头像点缀在气泡角上。
- 第一次成功保存（确认已经存进数据库之后）：一次性卡片「你的第一篇手帐完成啦！」，按钮［看看我的手帐］［回到首页］。不做庆祝动画。

### 3. 状态（存在 `little-days.onboarding`，和手帐数据分开）

```jsonc
{ "v": 1, "home": "new" | "done" | "skipped", "firstPage": "new" | "done", "at": "…" }
```

| 情况 | 结果 |
|---|---|
| 全新用户 | 自动开始。判断条件：既没有这个记录，也没有任何自己的页面和草稿，**不看示例数据** |
| 老用户升级 | 已经有自己的页面 → 直接标记 `done`，不打扰 |
| 跳过 / 自己探索 | `skipped`，不再自动出现 |
| 中途退出 App | 下次不再弹出（算跳过），设置里可以重看 |
| 设置 → 功能介绍 | 重看同一套高亮引导；不创建内容，不改数据 |
| 第一篇成功保存 | 显示一次完成卡片，`firstPage: done` |

### 4. 引导不能替界面背锅（同时要改的 UI）

- **页面管理找不到**：阅读器 ··· 里加「管理页面」（第一节），引导里不讲。
- **「完成」和返回的区别**：V10.51 已经改成返回自动保存，引导里不用再解释草稿。
- **换排版**：今天的故事里「换个排版」已经在底部；不进引导。

### 5. 实施难度与风险

- **难度中等**：
  - 高亮遮罩可以复用 Studio 教程的定位逻辑（`placeGuide`，测量真实按钮的位置）。
  - 首页按钮在屏幕下方时，先滚动再定位。
- **风险**：
  - 首页有 Captain 小人，引导气泡不能遮住被高亮的按钮。每一步都要用 375 / 430 宽、系统字体放大来测试。
  - 尊重「减弱动态效果」，VoiceOver 要读出每一步的文字和按钮。

**TestFlight 验收**：
- 删除 App 重装 → 自动出现欢迎；跳过后关掉再打开不会再出现。
- 设置里能重看；重看不创建任何页面。
- 老用户升级不会出现。
- 第一次保存后出现完成卡片，只出现一次。
- 小屏 iPhone 上气泡不遮按钮。

## 四、语音播放器的三种外观（同一个音频对象，三种皮肤）

### 1. 数据（不新增结构）

页面上的音频图层加一个可选的 `skin: "minimal" | "recorder" | "vinyl"`，缺省就是 minimal。
- 标题仍然是 `clip.name`。V10.50 已经修好播放；P1 标题编辑在设计确认后实施。
- 换外观只改 `skin`，音频文件、标题、时长、播放进度都不动。

### 2. 三种外观（设计预览第 4 块画板）

- **A · Minimal（默认）**：奶油纸色卡片、鼠尾草绿圆形播放键、20 根细声波条（按真实时长均分，播放到哪根就填色到哪根）、标题、时长。
- **B · 录音机**：
  - 一个横向小机身，扁平分层，不画金属反光；
  - 中间是两个磁带轮小窗，播放时慢慢转，暂停时停下；
  - 下面是标题标签纸和三个实体感按键（⏮ ▶ ⏭ 只做视觉，真正可点的只有播放键）；
  - 高度约是 Minimal 的 1.6 倍。
- **C · 黑胶**：
  - 一张奶油色唱片封套，黑胶从右边露出一半；
  - 唱片标签用鼠尾草绿，写标题；
  - 播放时唱片以每圈 6 秒的速度慢慢转，暂停时停下；
  - 整体是暖纸色，不是黑色的音乐播放器。

### 3. Challenge（请确认）

1. **性能**：
   - 黑胶和录音机都是 CSS 旋转（`transform`），一页上有几个音频也不成问题；
   - 但声波必须预先算好（一次解码、存成 20 个数值），不能播放时实时分析，否则省电和流畅度都会受影响；
   - 「减弱动态效果」打开时停止旋转，只保留进度。
2. **可访问性**：
   - 三种外观的可点区域都要至少 44 px；
   - 录音机上 ⏮ ⏭ 只是装饰，VoiceOver 不应该读到；
   - 黑胶旋转时，唯一的进度提示就是唱片在转——**必须另外显示时间**（例如「0:12 / 0:48」）。
3. **页面空间**：
   - 录音机和黑胶比 Minimal 大很多。建议这两种只用在「语音是这一页主角」的时候；
   - 照片页上默认还是 Minimal；
   - 换成大外观时，如果放不下，提示用户「这一页会重新排版」。
4. **操作直觉**：
   - 黑胶给人的期待是「转起来就在放」，所以加载中不能转，必须等到真正 `playing` 才转（V10.50 已经用真实事件）。
5. **替代方案**：
   - 与其三种完全不同的外观，不如**一个播放器 + 三种「纸」**：明信片、磁带标签、唱片封套。尺寸一样，排版不用变，工作量大约是三种外观的三分之一；
   - 如果你更想要动起来的黑胶 / 磁带，我建议先只做 **Minimal + 黑胶** 两种，录音机放到下一轮。

### 4. 编辑器里的交互（确认后实施）

- 选中音频后，工具栏显示：播放 / 暂停 · 标题 · 外观（三张带小预览的卡片）· 大小 · 图层 · 删除。
- 删除走现有的撤销；音频文件本身永远不会因为删除图层而被删。
- 拖动限制在纸张里，不会拖出可见区域。
