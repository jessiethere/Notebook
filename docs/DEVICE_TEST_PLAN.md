> 2026-11-13。只用专门的测试数据（仓库图库照片、模拟器录屏、自己拍的桌面照片），不用任何私人手帐。

## 2. 模拟器自动测试（Mac 上执行）

用 Debug 构建的 `-LittleDaysCheck` / `-LittleDaysTap`（只在 Debug 生效），流程见 `docs/MAC_LOCAL_DEV.md`。为了不碰 Mac 工作区里其他会话未提交的修改，构建用 `git archive` 导出的干净副本。

### 2.1 已做（2026-11-13，Debug 构建，提交 cc46e8d）

测试环境：新建的模拟器「LD B2 Check」（iPhone 17e，iOS 27.2），每次都先删除再重新安装 App。

| 启动参数 | `navigator.languages` | 界面 | 示例页 | 连续记录 / Keeper 邀请 | 「选今天的照片」底部 / 导航栏顶部 |
|---|---|---|---|---|---|
| `-AppleLanguages (en)` | `["en-US"]` | English ✅ | 无 ✅ | 都没有 ✅ | 448 / 773 px ✅ |
| `-AppleLanguages (zh-Hans)` | `["zh-CN"]` | 中文 ✅ | 无 ✅ | 都没有 ✅ | 423 / 739 px ✅ |

**结论**：iOS WKWebView 的 `navigator.languages` 会跟随系统语言，B2 在原生外壳里成立。

未覆盖：
- 真机；
- 第一次启动模拟器很慢：第一次渲染用了 98 秒，属于模拟器冷启动（MAC_LOCAL_DEV 记录过 26–45 秒的情况），不是 App 的问题，但没有在真机上测过速度。

### 2.2 还没做

2. **A3**：用 `-LittleDaysCheck` 读取 v138 同样的长文字在 iPhone 字体下的分页建议。

### 2.3 S1–S4（V10.41–V10.44）模拟器结果（2026-11-13，Debug 构建，提交 1076ce9 的 `Public/`）

测试环境同上（「LD B2 Check」，iPhone 17e，iOS 27.2）。脚本：`tools/mac/ios-sprint-check.js`（先删除再安装 App）和 `tools/mac/ios-sprint-restart.js`（**不**重装，只结束进程再打开）。照片是仓库图库里的 3 张（拍摄时间设为 08:10 / 12:40 / 19:20），没有用任何私人照片。照片选择器被跳过：文件直接交给页面自己的 `#attachment-image-input`，所以「iOS 相册选择界面」本身**没有**被测试。

| D1 新安装：只有一本空的「我的手帐」，没有家庭书、没有推荐书 | ✅ 1 本 | ✅ 1 本 |

第一次尝试失败的原因是测试脚本本身用错了文件输入框（`#photos-input`），不是 App 的问题：iOS 弹出了原生「照片图库 / 拍照 / 选取文件」菜单。改成首页真正使用的 `#attachment-image-input` 后通过。英文那次报告里的 `zh-CN` 是脚本在 App 设定语言之前就读了 `<html lang>`，现在等首页出现后再读。

**仍然只有浏览器测过、模拟器没测**：示例隔离的旧设备场景（v141 C/D）、Studio 里的换照片、删除共用照片的一页（v143）、PDF 导出、375 宽（iPhone SE 模拟器没装）。

### 2.4 S1–S4 真机步骤（还没做；需要一台个人 iPhone）

1. 删除 App 重装 → 书架只有一本空的「我的手帐」。

## 3. 真机步骤（约 20 分钟；需要一台个人 iPhone，例如 LZA 同意后的手机）

准备：

- 用 Xcode 直接安装（见第 4 节）。
- 在手机上拍 3 张桌面照片，录一段 5 秒的视频。
- **不要**用这台手机原来的任何私人照片做测试，也不要导入任何人的私人备份。

1. **首次打开（B1/B2/B3）**：截一张首页图。
   - 中文手机看到中文、英文手机看到英文；
   - 第一屏能看到「选今天的照片」；
   - 没有示例页。
2. **长文字（A3）**：
   - 选 1 张测试照片，用中文输入法打一段约 300 字（可以粘贴 `tests/v138-browser.cjs` 里的测试文字）。
   - 确认文字完整，并出现分页建议。点「分成 N 页」，保存。
3. **切后台（A2）**：
   - 新建一页，打一句话，**一打完立刻**按 Home 键回桌面，等 10 秒。
   - 从多任务界面把 App 划掉，重新打开。那句话应该还在。
4. **系统压力（A2）**：
   - 打开相机连拍 + 打开几个大 App，然后回到 Capiday。
   - 如果 App 重新启动了，检查刚才的内容是否都在。
5. **备份（C3）**：
   - 设置 → 导出完整备份 → 在分享面板里点「取消」 → 回答「没有」。「上次备份」不变。
   - 再导出一次 → 存到「文件 › 我的 iPhone」 → 回答「存好了」。显示今天的日期。
6. **恢复（C）**：
   - 删除 App → 重新安装 → 设置 → 从备份恢复 → 选刚才的文件。
   - 页面、照片、视频都在。
7. **读取失败保护（A1，观察项）**：
   - 正常使用中如果看到「手帐暂时没有打开」页面，请截图，点「保存原始数据副本」，然后把截图发给我。
   - 不要点其他按钮。

每一步之后：设置 → 检查照片和视频 → 「复制检查结果」，发给我（结果里没有文件名和文字内容）。

## 4. TestFlight 和直接用 Xcode 安装的区别

| | Xcode 直接安装 | TestFlight |
|---|---|---|
| 需要什么 | Mac + 数据线（或同一 Wi-Fi）+ 手机打开「开发者模式」 | 付费开发者账号（已有）+ 上传到 App Store Connect + 测试者装 TestFlight App |
| 安装的是 | Debug 构建（含 `-LittleDaysCheck` 等测试钩子，可以连 Xcode 看日志） | Release 构建（和上架版一样，没有测试钩子） |
| 有效期 | 付费账号签名约 1 年 | 每个构建 90 天 |
| 别人的手机 | 要把那台手机的 UDID 加到开发者账号设备列表；手机要和 Mac 连一次 | 只要发一个邀请邮箱或公开链接，对方不用连 Mac |
| 公司管理的手机 | 通常无法打开开发者模式 | 有的公司配置允许 TestFlight，有的不允许 |
| 第一次耗时 | 15–30 分钟 | 第一次上传 + 构建处理约 30–60 分钟；外部测试第一次要经过 Beta 审核（通常 1 天内） |

**建议：**

- LZA 的手机先用 **Xcode 直接安装** 做上面 1–7 步。它能看日志，最适合排查 P0。
- 等 5–8 位中文测试者时再用 **TestFlight**：内部测试最多 100 人且不需要审核；外部测试需要 Beta 审核。

需要注意：直接安装需要 LZA 的手机打开「设置 › 隐私与安全性 › 开发者模式」并重启，测试结束后可以关掉。
