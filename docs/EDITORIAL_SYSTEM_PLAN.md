# Track B · Editorial 自动排版系统 — 方案（第 1–3 步，等确认后实施）

> 2026-11-13。用户确认：Editorial 第一优先，Story 第二（先评估复用），Scrapbook 暂缓。
> 本文档是方案，**App 里还没有新的 Editorial**。设计板：https://claude.ai/artifact/J6P4SpkKuDn8eNn1CBGSDw （设计概念，不是 App 效果）。

## 0. 现状：引擎里已经有一个叫 editorial 的风格

`Public/js/scrapbook-layout.mjs` 的 `STYLES = ["editorial", "cozy", "playful"]`。现在的 `editorial`：

- 小号 kicker（`— 08:10 · MORNING`）；
- 照片无边框，单张横图出血；
- 一句话标题；
- 页脚 folio。

它和设计板 Editorial 的差别在**版式语言**，不在「用不用某个模板」：

| | 现在的 editorial | 设计板 Editorial |
|---|---|---|
| 页眉 | 时间 kicker | 刊头线：左 `LITTLE DAYS`、右日期，下方一条细线 |
| 网格 | 居中堆叠，宽度随照片定 | 8% 边距 + 12 栏网格；照片和文字落在栏线上 |
| 留白 | 内容垂直居中 | 有意的不对称留白（如 S1 的大日期数字占右下） |
| 文字层级 | 标题 / 正文两级 | kicker → 标题 → 正文（首字下沉）→ 编号图注，四级 |
| 多图说明 | 每张图下面一行字 | 照片只标 01/02…，说明集中成「图注索引」（S5） |
| 截图 / Meme | 和照片一样处理 | 细描边 + 偏移框，标 `截图`，和照片区分 |
| 长文字 | 照片下方正文 | 正文栏和照片栏并排（S7），或照片出血 + 下方双栏（S8） |

**结论**：不新建第四套引擎，而是把现有 `editorial` 升级成「规则驱动的 Editorial 网格」。cozy / playful 保持不动，避免影响旧页面。

## 1. 版式规则（把设计板变成可复用规则，覆盖 1–5 张）

页面是 4:5，单位为页宽 %。

### 1.1 网格与固定元素

- 边距 8%；12 栏，栏间距 2.4%。
- 刊头线：y = 4.6%。左边写 `LITTLE DAYS`，右边写日期（中文写「11月13日 周五」，英文写 `FRI · NOV 13`）。
- folio：页脚 97.6%，内容为 `NO. 13`。
- 内容区：y 从 11% 到 93%。

### 1.2 照片角色

照片按「宽高比 + 顺序」分配角色，不随机：

| 角色 | 条件 | 处理 |
|---|---|---|
| hero | 1–2 张中面积最大的横图或方图；或唯一一张 | 出血（单张横图），或占 8 栏 |
| column | 竖图（a < 0.9） | 占 5–6 栏，旁边放文字栏 |
| strip | 其余照片 | 等高横排，占 3–4 栏 |
| screen | 截图、Meme（a ≤ 0.62，或文件名、EXIF 判断为截图） | 细描边，标签写 `截图`，不出血，短边 ≥ 26% |

### 1.3 文字角色

用的是现有的 `lineFor`、`measuredBlock` 实测：

- **kicker**（时间 + 张数）：永远有，字号很小，用强调色。
- **标题**：≤ 2 行标题字号时用标题；更长的转为**正文**（A3 已实现的规则），中文两端对齐、行高 1.85，正文首字下沉。
- **图注**：
  - 1–2 张照片，有说明 → 放在照片下面，和照片同宽；
  - 3–5 张照片，有说明 → 照片只标 `01`…`05`，说明集中成索引，放在剩下的那一栏（S5）；
  - 索引放不下 → 回到「每张照片下面一行」。

### 1.4 按张数的候选结构

每种结构只是一个候选，先实测，再由 `checkQuality` 打分：

| 张数 | 候选结构（按优先顺序） |
|---|---|
| 1 | 横图出血 + 下方标题；竖图 6 栏 + 右侧大日期数字 / 文字栏；截图 6 栏描边 + 右侧引言 |
| 2 | 上大下小（hero + 右下 strip，左下文字）；左右等高；竖 + 横并排 |
| 3 | hero + 两张 strip；左 column + 右两张叠放 |
| 4 | 2×2 不等宽（S4）；hero + 三张 strip |
| 5 | 3 + 2 网格 + 图注索引（S5）；hero + 4 张 strip |

规则：

- 每种张数至少要有 3 个候选，这样「换个排版」才有三种可选。
- 候选都不合格（照片短边 < 20%、文字溢出、压到照片）时，走已有的分页建议（V10.34 / V10.38）。

### 1.5 中英文

- 中文标题用宋体或黑体（字体许可证见 library.json），英文用 Cormorant / Lora。
- 中英混排时按字符实测宽度，不按字数估算（已经有 L1 测量）。
- 语言切换只换界面里的刊头和 kicker（例如中文的「周五」、英文的 `FRI`）。**用户写的字不翻译。**

## 2. 接入现有引擎（第 2 步分析）

| 现有能力 | 位置 | 复用方式 |
|---|---|---|
| 实测文字 | `measuredBlock`、`MEASURE`（L1） | 直接用 |
| 质量检查 | `checkQuality`（L2） | 直接用，另外加两条：文字不压刊头（> 9%），不压页脚（≤ 93%，A3 已加在续页） |
| 备选排法与「换个排版」三选一 | `layoutChecked`、`arrangedPages` | Editorial 候选结构作为「style 自己的布局」，放在前面 |
| 分页建议（照片、文字） | `suggestSplit`、`suggestTextSplit` | 直接用 |
| 照片说明的数据 | `photo.caption` | 不变 |
| 手动调整保护 | `layoutEdited` | 不变：手动调整过的页面不会被重新排 |

需要新增：

1. `editorialCandidates(input, variant)`：按 1.4 节生成候选，放进 `layoutCore` 的 editorial 分支，替换现在的居中堆叠。
2. 生成层 `gen: true` 的刊头线、刊头文字、编号、图注索引，都是 text / deco 层。这样阅读器、PNG 导出、Studio 都能直接显示，不需要新的渲染器。
3. 截图识别：`aspect ≤ 0.62` 先当作截图。文件名或 EXIF 的判断以后再补。

**旧页面兼容**：

- 已保存页面的图层就是坐标，引擎升级不会改动它们。只有「新建页面」，或用户主动点「换个排版」才会用新规则。
- 手动调整过的页面（`layoutEdited`）永远不会被自动重排。

## 3. 风格绑定：Book Style 默认 + Page Style 覆盖（按用户的决定）

数据（都是可选字段，Swift `Models.swift` 同步加 `layoutStyle: String?`）：

- `book.layoutStyle`：书的默认风格。新书默认 `editorial`，旧书没有这个字段时按 `editorial` 处理。
- `moment.layoutStyle`：页面自己的风格。**已经存在**，不改。

行为：

| 操作 | 结果 |
|---|---|
| 新建页面 | `moment.layoutStyle = book.layoutStyle`（替换现在写死的 `story.style = "editorial"`） |
| 「换个排版」里换风格 | 只改当前页 |
| 改书的默认风格 | 只影响以后新建的页面；已保存的页面不重排，并提示「已有的 N 页保持原样」 |
| 手动调整过的页面 | 永远不自动变 |

- 不新增第二套布局数据：两种风格共用同一个引擎和同一种图层格式。
- 「设置书本风格」这一阶段先**不放 UI**，只预留数据字段。原因是 Scrapbook 暂缓，现在实际只有一种主力风格，没东西可选。

## 4. 验收标准（第 3 步）

两种检查都要过：

### 4.1 自动规则

每页都检查，沿用 v133 的检查：

- 照片短边 ≥ 20%（截图 ≥ 26%）、面积 ≥ 5.5%、不裁切；
- 文字不压照片、不出页、不压刊头和页脚；
- 中英文、375 / 430 两种宽度都要过。

### 4.2 人工评分

用 Visual Quality Rubric 的 8 项：

- 两个人分别给 8 组照片 × 中英文打分；
- 平均分 ≥ 设计板 Editorial 的 90%，才算达到设计板水平；
- 任何一组出现「不愿意直接保存」的判断，就要修改。

## 5. Story 复用评估（只评估，不实施）

Story 设计板的核心元素：

- 左侧时间轨（竖线 + 圆点 + 时间）；
- 按时间顺序的照片组；
- 长正文。

这些都可以用 Editorial 的网格加上 `gen` 层画出来（竖线是一个窄的 deco 层，圆点是一个 sticker 层）。所以 Story 可以做成**同一引擎里的另一组候选结构**，不需要新数据：

- 引擎已有 `moment.time`；
- 照片顺序就是 `layers` 的顺序。

估计 Editorial 完成后，再花 2–3 天可以做出 Story 的 1–5 张候选。

| 步骤 | 内容 | 估计 |
