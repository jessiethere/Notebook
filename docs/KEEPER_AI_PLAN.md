# Little Keeper：互动审查、三层陪伴、AI 小管家方案（2026-11-11 · Step 1 已在 V10.3 实现；AI 部分按用户决定暂缓，见第 10 节）

设计稿：Design 画布 https://claude.ai/artifact/4tXVQfHSSPvQxJZqJFPTUG 的「Little Keeper 快捷面板与四个流程」一板（8 个画面，393×852，在真实首页上注入原型后截图）。
画面里的 AI 回复是**示意文案**（人工写的示例），不是 Qwen 的真实输出；本轮没有调用任何模型，也没有发送任何手帐内容。

现状说明：App 里目前只有 Captain（`ANIMALS = ["cat"]`，V8.0 起）。Bunny 和 Westie 的性格在本方案里一并定义，功能系统三只共用，但它们的美术还没有接入。

## 1. 现有互动审查（代码：Public/js/keeper.mjs、app.js）

| 场景 | 现在怎么回应 | 问题 |
|---|---|---|
| 首页点 Captain（温柔模式） | `keeper.tap.0–3` 四句按点击次数轮换：嘿嘿，被你发现了 / 今天有什么想记录的吗？/ 今天不写也没关系哦 / 你的手帐越来越好看了 | 只有 4 句，点 5 次就重复；完全不看状态——今天已经写了 3 页，它还问「今天有什么想记录的吗？」 |
| 首页点 Captain（互动模式） | 打开聊天面板，开场固定「我在呢。想一起回看，还是整理一下书架？」 | 每次相同 |
| 聊天里打字 | 无论输入什么，都回「嗯，我听到了。想把它写进今天的一页吗？」 | **最鸡肋的一处**：有输入框却不理解任何内容 |
| 聊天三个快捷项（回看回忆 / 这周写了什么 / 看看书架） | 本机查数据后套模板 | 能用，但句式固定；「回看回忆」随机抽一页，可能连续抽到同一页 |
| 保存一页后「听听 Captain 怎么说」 | 关键词正则 → 开头 + 中段 + 结尾三段拼接，每段 2–3 句候选，末尾固定加「（尾巴晃了晃）」 | 读起来像拼出来的；没命中关键词时总是「谢谢你把今天写下来。每一小步都算数。」；正则粗（出现「吃」就当成吃饭）；动作括号每次都有 |
| 书架上点 Captain | 三句轮换（有 N 本 / 最近收进来的是 / 加个标签吧） | 所有手帐都有标签时仍然建议加标签 |
| 按时间的问候 `keeper.prompt.*` | 早 / 午 / 晚 / 夜各一句 | 首页已经有「Hi！今天是星期三 · 今天有什么值得记录？」，再说一遍是重复（V8.0 已默认不自动弹出，文案仍在） |
| 长大提示 | 「我好像长大了一点点 —— {阶段}」 | 第三个阶段名就叫「Little Keeper」，读起来奇怪 |
| 引导页隐私说明 | 「它说的话都在这台设备上生成」 | 现在属实；接入 AI 后必须改写，否则变成不实陈述 |

结论：问题主要不是「没有 AI」，而是**固定文案不看上下文、候选太少、时机重复**。其中大部分可以不用 AI 修好（见第 2 节的第 1、2 层），应先做。

## 2. 三层陪伴能力

| 层 | 做什么 | 触发 | 数据 | 需要 AI |
|---|---|---|---|---|
| ① Natural Companion | 轻微动作和表情：探头、眨眼、被点时弹一下、打字时安静、夜里困、保存后开心 | 自动，但只是动画，不说话 | 不读内容 | 否 |
| ② Contextual Companion | 按**真实产品事件**说一句：今天第一页 / 第 N 页、连续第 N 天、隔了几天回来、放进了照片或声音、某本手帐写满 10 页、那年今天、待办都做完 | 事件发生时最多一句；点它时按当前状态选句；同一句 7 天内不重复；每天主动最多 1 次（互动模式且已授权时） | 只用计数、时间、书名、标题这类本机元数据 | 否 |
| ③ AI Companion | 用户**主动**发起：整理今天的故事、回顾回忆时「讲讲这一页」、帮我写一句话、自由聊天 | 只在用户点了对应操作并确认发送内容后 | 用户勾选的页面文字，或用户输入的那句话 | 是（可完全关闭） |

原则：AI 不取代 ①②。AI 关闭、离线、失败时，①② 照常工作；③ 的每个入口都有本机降级结果。

第 ② 层的句子按「状态 × 性格」准备：每个状态每只角色 6–8 句，记录最近用过的句子 ID（现有 `keeper.recent` 机制）避免重复。去掉固定的「（尾巴晃了晃）」后缀，动作交给第 ① 层的动画。

## 3. 什么时候用预设、什么时候调 AI

| 情况 | 用什么 |
|---|---|
| 点一下 Captain、事件回应、问候、长大、书架提示 | 预设（第 ② 层） |
| 回顾回忆：找哪一页 | 本机查找，不用 AI |
| 这周写了什么、书架整理 | 本机统计，不用 AI |
| 整理今天的故事（小结、排序建议、一句话） | AI；用户先勾选页面并确认。也提供「只在本机整理」：按时间排好、列出标题，不生成文字 |
| 「讲讲这一页」 | AI；仅该页文字，确认后发送 |
| 帮我写一句话 | AI；只发送用户输入的那句话（可选附上当前页标题） |
| 自由聊天 | AI；只发送这段对话。AI 未开启时，本机按关键词转到上面几项，并如实说「我现在只会这几件事」，不再对任何输入回同一句 |
| 任何 AI 请求失败 / 离线 / 超时（建议 8 秒） | 本机降级回应 + 「再试一次」；不自动重发 |

## 4. 首页入口与快捷面板

- **两个入口，同一个面板**：点 Captain；或点 Captain 旁边的小标签「找小管家 / Ask Keeper」（像它身上挂的一个小牌子，13px、纸色、不实心）。不加底部 Tab，不做悬浮聊天按钮，不动照片手帐主卡。Keeper 关闭时入口不出现。
- **面板（Bottom Sheet）**：角色图 + 名字 + 陪伴方式；一句按当前状态生成的欢迎语（第 ② 层，不是固定句）；输入框；四个操作用**一列四行**（线性图标 + 名称 + 一行说明 + ›），不是宫格；底部一行如实说明当前是否会发送内容。
- **四个操作的流程**
  1. 整理今天的故事：勾选页面（默认勾选今天的页面，可取消）→ 一块说明「会发送 / 不会发送 / 由谁生成」→「发给 AI 整理」或「只在本机整理」→ 结果是建议卡片（一句话小结、排序建议）→「放到封面（先预览）/ 换一种说法 / 不用了」。采纳后进入编辑预览，用户确认才写入，并进入撤销历史。
  2. 回顾以前的回忆：本机挑一页（避开最近看过的）→「翻开这一页 / 换一页 / 让 Captain 讲讲这一页 · AI」。只有最后一项会发内容，且再确认一次。
  3. 帮我写一句话：输入大概的意思 → 三种写法（简单 / 温柔 / 角色口气）→「用这一句（先预览）/ 再来三句」。
  4. 和 Captain 聊聊：短对话；每条 AI 回复下标注来源和发送范围。不是完整聊天室：不保存历史到手帐，关掉面板即清空，最多保留最近 6 轮作为上下文。

## 5. Captain 三个场景：固定回复 vs AI 回复（AI 一栏为示意）

设定：今天写了 2 页——「下午的咖啡好治愈」（3 张照片，正文：和小林在街角那家店坐了一下午，聊了很多以后想去的地方）和「傍晚的散步」。

| 场景 | 现在（代码里的真实文案） | 第 ② 层改进后（预设，不用 AI） | 第 ③ 层 AI 示意 |
|---|---|---|---|
| 点一下 Captain | 「今天有什么想记录的吗？」（已经写了 2 页仍这样问） | 「今天收了 2 页。咖啡那页，我偷偷多看了两眼。」 | 不调用 AI（点一下不值得一次请求，也不该为此发送内容） |
| 完成一页（听听它怎么说） | 「谢谢你把今天写下来。有人一起，日子会更有温度。每一小步都算数。（尾巴晃了晃）」 | 「这页有三张照片——今天的咖啡很上镜。」 | 「一下午的咖啡，换来一张想去的地方的清单，很划算。哪天真去了，记得回来翻这一页。」（仅在用户点「听听它怎么说」且已授权时；只发送这一页的标题和正文） |
| 请它整理今天的 Moments | 没有这个功能；聊天里输入这句话得到「嗯，我听到了。想把它写进今天的一页吗？」 | 本机整理：按时间列出两页，建议把照片最多的一页放前面 | 「今天的一句话：一杯咖啡聊到天色变暗，回家的路上又多走了一段。咖啡那页适合当封面。」+ 采纳 / 换一种 / 不用了 |

差异小结：固定回复的问题是「不知道今天发生了什么」；第 ② 层用本机元数据就能解决一大半（知道几页、几张照片、哪本手帐）；AI 的增量在于**读了文字之后的具体回应和代写**，所以只放在用户主动、明确授权的三件事上。

### 三只角色的语气（共用功能与接口，只换 persona 和动画）

| | 性格 | 说话方式 | 避免 |
|---|---|---|---|
| Captain | 好奇、呆萌、偶尔调皮 | 短句，爱观察细节（「三张照片的那种好喝」），偶尔自嘲 | 说教、连续感叹号、撒娇过头 |
| Bunny | 温柔、乐观、鼓励 | 轻声、肯定具体的小事 | 空泛的「你真棒」、强行正能量 |
| Westie | 热情、活泼、忠诚 | 语速快一点、直接表达高兴 | 过度兴奋、每句都喊名字 |

系统提示词骨架（三只共用，替换 persona 段）：角色与语气 → 硬规则（1–3 句；不诊断、不评判；难过的日子不强行积极；不编造没给它看的内容；不声称记得以前；不提醒打卡；不用表情符号堆砌；用用户的界面语言；建议只是建议）→ 本次任务（整理 / 讲讲这一页 / 代写三句 / 闲聊）→ 用户授权的内容 → 输出格式（JSON：`reply`，可选 `suggestions[]`、`order[]`）。温度 0.7 左右；服务端校验长度和格式，不合格则退回本机回应。

## 6. Qwen API 可行性

以下价格与接入信息来自 2026-11-11 的网络检索，**二手来源之间有出入，接入前必须以阿里云 Model Studio 官方价目页为准**（来源见文末）。本轮没有实测延迟和中英文质量——没有 API Key，也不应在未确认前调用。

- **接入方式**：阿里云 Model Studio（百炼 / DashScope）提供 OpenAI 兼容接口。国际站（新加坡）`https://dashscope-intl.aliyuncs.com/compatible-mode/v1`，中国内地（北京）`https://dashscope.aliyuncs.com/compatible-mode/v1`；Key 分地域，用 Bearer 方式发送。因为是 OpenAI 兼容格式，换供应商只需改 base URL、模型名和 Key。
- **模型档位与价格（新加坡，每百万 token，二手来源）**：Flash 档约 $0.14–0.15 输入 / $0.42–0.47 输出；Plus 档约 $0.40 / $1.60；Max 档约 $2 / $6。新账号有 100 万 token、90 天的免费额度（仅新加坡端点）。
- **建议**：默认用 Flash 档（短回复、低延迟、便宜）；「整理今天的故事」可选 Plus 档。先用免费额度做一次中英文质量与延迟的小样本评测（约 30 条合成手帐，不用真实日记）再定。
- **单次成本估算**（按 Flash 档 $0.15 / $0.47）：一次回复约 800 token 输入（系统提示 350 + 授权内容 400 + 输入 50）+ 120 token 输出 ≈ **$0.00018**；「整理今天」约 1500 + 300 ≈ **$0.00037**。Plus 档约为 3 倍。
- **月成本估算**：每位活跃用户每天 3 次 → 每月约 $0.02（Flash）；1000 位月活约 **$18 / 月**（Flash）或约 $55 / 月（Plus）。后端代理本身用无服务器函数，这个量级基本在免费额度内。以上是估算，不含税和汇率。
- **延迟**：未实测。Flash 档配合流式输出，预期首字在 1 秒左右、整句 2–3 秒；需要在目标地区实测（内地用户连新加坡端点、海外用户连北京端点都会变慢）。界面按「8 秒超时 → 本机降级」设计。
- **上下文管理**：不在服务端保存对话。客户端每次带上最近 6 轮对话 + 本次授权的内容；关掉面板即清空。不做长期记忆（「不声称记得以前」）。
- **成本控制**：每设备每日上限（建议 20 次，可调）；单次最大输入 2000 token、输出 300 token；点一下角色和事件回应永不调用 AI；相同请求 30 秒内不重复发送；服务端设月度预算告警和硬上限，超限后全体降级为本机回应。

### 架构（保留换供应商的能力）

```
iOS 外壳 / 网页（Public/）
  └─ keeper.mjs  createFeedbackService({ remote })   ← 现有接口，remote 目前是 null
        └─ remote.respond(request)  →  HTTPS  →  我们自己的后端代理 /v1/keeper/respond
                                                  ├─ 校验设备令牌、限流、截断长度
                                                  ├─ 拼系统提示词（persona 在服务端，不在客户端）
                                                  ├─ ModelProvider 接口：QwenProvider（现在）/ 其他（将来）
                                                  └─ 不落盘请求正文；只记计数和耗时
```

- **API Key 安全**：Key 只存在后端环境变量里。客户端（包括 iOS 包和网页）里没有 Key，也没有直连 DashScope 的代码。后端入口用匿名设备令牌 + 限流；上架 iOS 后可加 App Attest。
- **后端放哪**：仓库里已有 Vapor 服务入口，可以加一个路由；或用一个独立的无服务器函数（更省事）。这需要你提供云账号并决定地域——本轮不创建。
- **在线预览链接**：claude.ai 的固定链接对外部网络请求有限制，AI 功能在那里很可能不可用，会一直走本机降级；真实效果要在 iOS 外壳或 localhost 里验证。
- **离线降级**：检测到离线或 `remote` 不可用时，面板里 AI 操作显示「现在连不上，先用本机的」并给出第 ② 层结果。

## 7. 隐私与授权

- 私人手帐默认只在本机。AI 是**单独的开关**（设置 → 数据与隐私 → AI 小管家），默认关闭；开启 Little Keeper 不等于开启 AI。
- 开启时的一次性说明页：发给谁（Qwen，阿里云，哪个地域）、发什么、不发什么、怎么关。之后**每次**发送页面内容前仍显示「会发送 / 不会发送」并需要点确认；只发送一句输入的话（帮我写、闲聊）时不再弹确认，但回复下方标注发送范围。
- 永不发送：照片、视频、声音、未勾选的页面、其他日子、名字、书名以外的任何账号信息。永不自动读取全部日记。
- AI 生成内容只是建议：放进手帐前先预览，用户确认才写入，可撤销；不会覆盖原文。
- 可完全关闭；关闭后不再有任何网络请求，第 ①② 层照常。
- 接入前必须核实并写进说明页的事项（本轮未核实）：阿里云对 API 输入输出的保留期限、是否用于训练、所选地域的数据存放位置。
- 现有文案「它说的话都在这台设备上生成，你的日记不会被发送到任何地方」在 AI 开启后要改成分情况的准确说法。

## 8. 与现有系统的整合

- 复用：三种陪伴方式和关闭；`keeper.aiConsent`（已存在、目前不可打开）；`createFeedbackService({ remote })` 的远程钩子；`modeAllows()` 权限判断；`keeper.recent` 去重；聊天面板的 Sheet。
- 新增（确认后）：首页入口标签；面板改版与四个流程；第 ② 层的状态选句器和句库（三种性格）；`remote` 客户端；后端代理；设置里的 AI 授权与说明页。
- 不做：完整聊天室、长期记忆、主动推送的 AI 消息、喂养 / 签到、独立 Growth 模块、角色美术改动、Journal Studio 改动。

## 9. 建议的实施顺序（等你确认）

1. **先修互动（不用 AI）**：第 ② 层选句器 + 句库、去掉动作后缀、聊天输入的本机意图识别、首页入口与新面板、「回顾回忆」「本机整理」两条不用 AI 的流程。这一步就能明显改善「鸡肋」。
2. **AI 评测**：用免费额度和合成手帐评测 Qwen Flash / Plus 的中英文质量、延迟，并核实数据条款；给你看真实输出再决定。
3. **接入**：后端代理 + 授权流程 + 三个 AI 操作 + 限额与降级。

需要你决定：是否按这个顺序；云账号与地域（新加坡 / 北京）；每日限额和月度预算上限；默认模型档位。

- 与本方案的差异：「回顾回忆」的许可从「仅互动方式」放宽为「温柔 / 互动方式 + 用户明确同意」（在面板里问一次，可在设置关闭）；面板里的「帮我写一句话」如实标为需要 AI、尚未开放；第 6–7 节的云端方案仅作将来参考。
