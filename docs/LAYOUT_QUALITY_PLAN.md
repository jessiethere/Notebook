# 自动排版质量规则与建议分页（L1–L3 已实施：V10.33 / V10.34；L4 待 iOS 校准）

> 2026-11-13 用户确认方向并补充：
> - 20% / 5.5% 是初始下限，要用真实页面校准；
> - 1/3 是软规则，允许有设计意图的主图 + 配图；
> - 长文字按实际渲染行数判断；
> - 真实字体测量提前到 L1；
> - 分页要给出单页与多页的对比，由用户选择。
>
> 实施时的校准：真实页面里，9:16 Meme 在 20% 宽时上面的字只有约 8 px，所以把很高的图片（宽高比 ≤ 0.62）的短边下限提到 26%。实施细节见本文末尾「实施记录」。

> 2026-11-13。原则：*Beautiful pages over crowded pages.*

## 1. 三个问题的根因（代码和浏览器测量核对过）

| 问题 | 根因 |
|---|---|
| 9:16 竖图 + 三张照片 + 长文字，竖图约 11% 宽 | ① 长文字被当成大标题：19 号、4 行，先占约 30% 页高；② 大照片再拿剩余高度的 60%；③ 同一行照片「等高」，9:16 只能很窄；④ 没有最小尺寸检查（V10.30 只拦宽度 < 14% 的情况） |
| 五张竖图都写字，有一句压到照片约 10% | ① 照片说明最小宽 26%，比 19% 宽的照片还宽，向两边伸出，分别压到左右两张照片 5% 和 6%；② 检查允许「每样东西各压 6% 以内」；③ 文字高度靠字数估算，Chromium 实测 225 种组合里有 20 种多出一行以上，最多是估算的 1.67 倍（中文标点不能放在行首、英文按整词换行、大写字母更宽）；④ 这时三种排版完全一样，「换个排版」出现三张相同的小图 |
| 三张照片 + 长文字，下面两张太小 | 和问题 1 同源：长文字先占 30%，大照片再占 60%，下面两张每张约 4.3% 页面；文字区是最后扣掉的，没有和照片一起算 |

## 2. 规则（建议值）

- 照片短边 ≥ 页面宽 20%（iPhone 页面上约 70 px）。9:16 量宽，16:9 量高。
- 照片面积 ≥ 页面 5.5%（约 90 × 90 px）。
- 大小平衡：≤ 4 张时，最小的一张 ≥ 最大一张的 1/3；5 张以上时 ≥ 1/5。主照片太大时先缩主照片，不判失败。
- 文字压照片 = 0（只留 0.3% 计算误差）。拼贴风格允许照片之间轻微重叠，但文字不能压照片。
- 文字不出页面（四边留 1%）；文字之间不重叠。
- 无意义空白：照片和文字之间的空带 ≤ 24% 页高。页边和整体居中的留白不算。
- 间距：照片之间 2.4%，照片和它的字之间 1.2%（和现在一样）。
- 照片说明宽度 = 照片宽，不再伸出照片。
- 长文字：14 字以内用 24 号标题，28 字以内用 21 号，再长的用 16 号正文（约 17 px），最多 6 行，不截断。
- 文字测量：模拟浏览器的换行（英文整词、中文标点不放行首、宽字母更宽）。正式版在 App 里用真实字体量。
- 不裁切；截图和 Meme 上的字保持完整。

## 3. 单页 / 建议分页

1. 先按现在的方式排。通过规则就保持原样，一点不变。
2. 不通过时，依次试三种结构，选全部通过且得分最高的一种：
   - 整齐的几行：每张照片有最小宽度，窄照片可以比同行的高一点，不会被压窄；主照片太大时缩小主照片那一行；
   - 两栏：两栏底部对齐；
   - 竖图单独一栏，其它照片在旁边排成几行。
3. 都不合格时，在「今天的故事」底部显示建议卡「放在一页会太挤，分成 2 页？」，附两页预览：
   - 〔分成 2 页〕：照片按原来的顺序分开，那句话在第一页，每张照片的字跟着照片走。复用「调整照片分组 → 从这里分开」；
   - 〔保持一页〕：用问题最少的方案，文字仍然不压照片。
4. 不会自动加页，不覆盖已有页面，已保存的页面不重新排版。

## 4. 原型结果

- 规则矩阵：每种风格 480 页，组合方式是 1–8 张照片 × 无 / 短 / 中文长 / 英文长 / 中英混排 × 有无每张照片的字 × 3 种排版。

  | 风格 | 现在不合格 | 原型合格 | 其中和现在完全一样 | 建议分页 | 仍不合格 |
  |---|---|---|---|---|---|
  | 杂志 | 302 | 414 | 114 | 66 | 0 |
  | 手账 | 220 | 345 | — | 135 | 0 |
  | 拼贴 | 318 | 381 | — | 99 | 0 |

- 375 中文 / 430 英文真实流程：8 个案例都跑通，修复前后截图见预览页。案例包括 1 张 9:16、4 张含 9:16 + 长文字 + 说明、5 张竖图全写字、3 张 + 长文字、2 横 + 1 竖、6 张建议分页、英文长文字、中英混排 + 宋体 + 大一号。走过选照片 → 写字 → 改字体 → 预览 → 分页 → 保存 → 阅读器。
- 速度：大多数页面 4–50 ms。需要建议分页的页面最多约 0.4 秒；正式版只在需要时才计算。
- 没测：iPhone 真机和模拟器的真实字体测量；手账和拼贴风格的逐张截图检查（只跑了规则矩阵）。

## 5. 对已有手帐和数据

- 已保存的页面不变：排版只在「今天的故事」里新建或重排时运行，旧页面的位置存在图层里。
- 不加新字段：分页的结果是两个时间相同的 Moment。质量检查的结果只放在内存里。
- 以后如果要在阅读器里把两页标成「续页」，可以加可选字段 `continues`，并同步 `Models.swift`。这一轮不做。

## 6. 分阶段实施（确认后）

1. **L1**：质量检查、按真实换行测量、长文字改成正文、照片说明不超过照片宽；合格的页面保持原样；单元测试用规则矩阵。
2. **L2**：三种备选结构；「换个排版」不再出现重复的小图；浏览器测试覆盖需求里第六节列出的全部案例。
3. **L3**：建议分页卡和两页预览，〔分成 2 页〕〔保持一页〕；测试照片、说明、顺序和那句话都保留。
4. **L4**：App 里用隐藏元素量真实字体；在 iOS 模拟器里核对 PingFang。


## 实施记录（2026-11-13）

- **L1 测量与规则**（`scrapbook-layout.mjs`）：
  - 排版时 App 提供 `measure(text, size, width, fontId, weight)`（`app.js` 的 `measureWords`）。它在屏幕外一张 1000 px 宽的页面上，用和画布相同的 CSS 渲染文字，量出真实高度。字体还没加载完时返回 null，引擎改用偏保守的换行计数（`wrapLines`：英文整词换行，中文标点不放行首，宽字母算宽一些）；字体加载好后，正在做的故事会重新排一次。
  - 文字按最终显示的字体和字重测量：页面选了字体就用那个字体，不再先按风格默认字体排，再换成用户的字体。
  - 那句话能在标题字号下排成两行以内就保持标题；否则用 16 号正文（乘以页面字号档位），不缩小、不截断。
  - 照片说明和照片一样宽，最小字号 10（页面实际显示的最小字号）；压在别的东西上的容忍度从「每样 6%」改成「总共 0.3%」。
  - 质量检查 `checkQuality`：
    - 硬规则：照片短边不小于 20%（很高的图片 26%）、面积不小于 5.5%；文字不压照片、不压文字、不出页面；照片不出页面；杂志风格里照片不重叠。
    - 软规则：大小平衡（不超过 4 张时最小的约是最大的 1/3）、无意义的空白带。
- **L2 备选排法**：风格自己的三种排版先检查。合格的照片位置和以前完全一样。不够三种合格时，再试：
  - 整齐的几行（窄照片保留最小宽度，主图过大时缩小主图那一行）；
  - 两栏；
  - 高图单独一栏，其它照片排成几行。

  每张照片的字都在它正下方；照片保留风格的相框、轻微倾斜和胶带。「换个排版」只给出合格且互不相同的排版，不再出现重复的小图。
- **L3 建议分页**：`suggestSplit` 只在没有任何合格单页时使用，按顺序分成 2–4 页，每页都必须合格。「今天的故事」里显示建议卡：「现在 · 一页」和分开后的每一页，按钮〔分成 N 页〕〔保持一页〕，并写明「保持一页时，有的照片会比较小，或者排得比较挤」。分页复用照片分组：那句话在第一页，每张照片的字跟着照片，每页都保留整页的字体设置。选了〔保持一页〕后，「换个排版」里仍可以重新分页。
- 顺带修复：Quick Edit 换照片后再「调整照片分组」会把旧照片换回来（分组里存的还是旧引用）。现在换照片时分组一起更新，撤销时一起恢复。
- 已保存的页面：引擎只在「今天的故事」里新建或重排时运行；字体加载后的重排也只针对正在做、没有手动调整过的页面。
- **L4（未完成）**：在 iOS 模拟器里用真实字体（PingFang 等）核对测量和页面。Mac 在这段时间里没有响应。
