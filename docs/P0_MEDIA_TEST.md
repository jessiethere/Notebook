# P0 媒体持久化 — 实际 App 验证步骤与当前结论

> 2026-11-13。只用测试媒体，不清理、不重置任何现有数据。
> Claude App 内嵌链接（Web Preview）和原生 iOS App（Xcode 模拟器）**分别测试**，结果不能互相代替；设计板里的 localStorage / IndexedDB 自测**不等于**这里的测试。

## A. Claude iOS App 内嵌链接（用户在 iPhone 上做，约 5 分钟）

准备测试媒体：用相机拍一张不含私人内容的照片（比如桌面），再录一段 3–5 秒的视频。

1. 在 Claude App 打开固定链接（V10.26 或更新），首页点「只写字」。
2. 在页面上写一行字：`P0-TEST-` 加现在的时间（例如 `P0-TEST-0915`）。
3. 点底部「照片」加上刚拍的照片；再从「更多 → 视频」加上测试视频，等卡片显示「已保存」。
4. 看到右上角「已保存」后点「完成」。
5. **场景 1 · 离开再进来**：回首页 → 打开刚才那一页。记下：文字在不在、照片 / 视频是正常显示还是 Error。
6. **场景 2 · 切到后台**：切到别的 App 30 秒再回来，看同一页。
7. **场景 3 · 完全关掉 Claude**：从多任务界面把 Claude 划掉 → 重新打开 Claude → 打开固定链接 → 找 `P0-TEST` 那一页。记下：
   - 那一页还在不在（文字 `P0-TEST-…` 在不在）；
   - 照片 / 视频是正常、Error，还是不见了。
8. 每个场景之后：设置 → 检查照片和视频 → 「复制检查结果」，发给我（结果里没有文件名和文字内容）。

怎么看结果：

| 你看到的 | 说明 |
|---|---|
| 文字和照片都在 | 这一场景没问题 |
| 文字在，照片显示 Error 或「照片读取不到」 | 页面数据在，媒体文件读不出来 → 媒体存储的问题，检查结果里会写是哪一类 |
| 文字也不见了（整页没了） | 整个本地存储被清掉了 → 宿主环境（Claude App 的内嵌网页）的行为，不是只丢了照片 |
| 视频那一行写「视频没有打开检查」 | 不是坏了：iOS 要先点一下才读取视频 |

## B. 原生 iOS App（Xcode 模拟器）

### 已经自动做过的（2026-11-13，Debug 构建，提交 c539dfc → 3bc6ee9，模拟器「LD P0 Verify」iOS 27.2）

用只在 Debug 构建生效的 `-LittleDaysTap "upload:…"` 把测试文件交给页面自己的文件输入框，之后走的就是 App 真实的导入和保存代码；跳过的只有系统的照片选择器。

| 测试 | 结果 |
|---|---|
| 测试照片（仓库图库照片 latte-art）→ 加到页面 → 杀掉 App → 重新打开 | ✅ 照片显示正常；检查：页面用到 1 · 存着 1 · 正常 1 |
| 测试视频（模拟器录屏 H.264，0.1 MB，5.8 秒）→ 导入 | ❌ 卡在「导入」这一步：`media-timeout`（10 秒内读不到视频信息）。同一个文件在 Mac 的桌面 WebKit 里 0.1 秒就读到了 |
| 包含测试照片 + 测试视频的备份 → 用「恢复备份」导入 → 杀掉 App → 重新打开 | ✅ 页面用到 3 · 不在 0 · 读不出 0；照片显示，视频显示封面，信息「0:05 · 0.1 MB · 已保存到本机」 |
| 同一个视频的检查 | 以前写成「解码失败 · timeout」，V10.26 改为「视频没有打开检查（iOS 要先点一下才读取视频，不代表坏了）」 |

视频导入失败的原因（**推断，未完全证实**）：iOS 的 WebKit 只在用户点了屏幕之后才加载视频数据；我用脚本交文件，没有「用户点击」，所以视频信息一直不加载。真实的系统选择器是用户点选的，很可能不受影响，但这一步只能手动点选来验证。

### 还要手动做的（在 Mac 上，约 5 分钟）

1. Xcode 打开 `LittleDays.xcworkspace`，选模拟器「LD P0 Verify」，按 ⌘R。
2. 首页点「只写字」→ 写 `P0-TEST-SIM` →「照片」从相册选一张（相册里已有测试图）→「更多 → 视频」选一段测试视频（模拟器相册里有之前放的 10 秒 mp4）。
3. 等视频卡片显示「已保存」，点「完成」。
4. 在模拟器里按 ⇧⌘H 回到主屏，再从多任务里划掉 Little Days（或在 Xcode 里按 ■ 停止）。
5. 重新打开 App，打开 `P0-TEST-SIM` 那一页：照片、视频是否正常；点视频能否播放。
6. 设置 → 检查照片和视频，截图。

## C. 目前的结论

**已证实**
- 原生 iOS App（模拟器）里，照片按 App 真实路径保存后，杀掉 App 再打开仍然正常。
- 原生 iOS App 里，已经存进去的视频字节在杀掉 App 后仍然存在、可以读出，封面正常显示。
- 旧的「检查照片和视频」在 iOS 上会把视频误报成「解码失败」，V10.26 已改正。
- 你在 Claude App 里的检查截图：内嵌网页，长期保存 = 否，没有媒体被引用，没有错误记录。

**未确定**
- 你最早看到的 Error 的根因。当时的数据已经不在，检查里也没有记录。
  - 可能性 1：V10.21 之前把 File / Blob 直接存进 IndexedDB，iOS WebKit 里这种 Blob 可能失效。V10.21 已改成存字节。
  - 可能性 2：Claude App 关闭后，内嵌网页的本地存储被清掉。
  - 要靠上面 A 的场景 3 来区分。
- 在真实 iPhone 的系统选择器里导入视频，是否也会遇到 `media-timeout`。
- 原生 App 在**真机**上的表现。模拟器通过不等于真机通过，也不能据此断言原生 App 一定不受类似问题影响。

**可能的修复（等测试结果再决定，未实施）**
- 如果确认 iOS 上视频信息加载依赖用户点击，就改为直接从 MP4 / MOV 文件头读取时长和尺寸，不依赖 `<video>` 元素。
- 如果确认 Claude App 关闭后存储会被清掉，就在内嵌链接里明确提示「这里只是预览，长期记录请用 App 或定期备份」。宿主行为，App 代码修不了。
