# P1 · 照片分组与故事顺序（Smart Photo Grouping & Story Ordering）

> 2026-11-14 · **只是方案和交互设计，没有改生产代码，也没有改数据库。** 等用户确认后再分阶段实施。
> 设计预览（375 / 430 宽，中英文）：https://claude.ai/artifact/9keLMFJh3q5vwTfaSycKo2

原则：**自动建议，用户决定**（Auto-suggest, User decides）。

- 默认只是「建议分组」；不同时间的照片可以放在同一页。
- 不再因为「隔了 90 分钟」就强制拆成新的一页。
- 用户确认之前，不把多页写进已保存的手帐。
- 「分组」（哪些照片在同一页）和「排版」（照片在页面上怎么摆）是两件事，分开操作。

---

## 1. 现在的分组代码路径与触发条件

| 步骤 | 位置 | 做了什么 |
|---|---|---|
| 选照片 | `Public/app.js` `handleImageUpload`（约 10640 行） | 只有 `target.kind === "quick"`（首页 / 今天怎么记 → 照片）会在压缩前用 `photoTime(file)`（`Public/js/exif.mjs`）读拍摄时间：EXIF 优先，其次文件时间。照片写进 IndexedDB `little-days-media`，得到 `media:<uuid>`。 |
| 分组 | `Public/js/day-story.mjs` `groupByTime(items, gap = STORY_GAP_MINUTES)` | `STORY_GAP_MINUTES = 90`。按拍摄时间排序（没时间的照片跟在前一张后面），**相邻两张相差超过 90 分钟就开新组**。 |
| 生成 | `app.js` `startStory(groups)` → `makeStory()`（约 4578 / 4789 行） | 每组立刻生成一个 Moment（一页）：`time: clockLabel(group.start)`、`capturedAt`、照片图层；然后 `layoutStory({ force: true })` 排版，`flushDraft()` 写入**草稿**。 |
| 调整（创建中） | `storyAction`：`story-group` / `story-move`（‹ ›） / `story-split` / `story-remove` / `story-regroup`；`story-split-pages`（排版质量建议拆页） | 「调整照片分组」页：照片只能往前一组 / 后一组挪一格，或「从这里分开」。**没有「合并两组」「全部一页」，组内顺序固定为拍摄时间。** |
| 保存 | `finishStory()`（约 5345 行） | 点「保存」才写进已保存的手帐（`saveEntry`）。 |
| 已保存之后 | 页面目录 `renderPagesManage`：`page-move` ↑↓、复制、删除；Studio 图层「上移一层 / 下移一层」 | 页序可以调；**照片不能移到另一页，页不能合并或拆分，页内照片顺序只能靠图层顺序间接改。** |

**问题归纳**

1. 90 分钟是硬规则：上午 10:00 和 11:45 的同一次出门会被拆成两页，用户要自己一张张挪回去。
2. 一进来就生成了 N 页（虽然只写在草稿，没有写进已保存的手帐），用户第一眼看到的是「被拆好的结果」，而不是「建议」。
3. 没有「全部放在一页」「自己分组」的入口。
4. 组内顺序 = 拍摄时间排序后的顺序；照片在页上的顺序 = 图层数组顺序，**和叠放顺序（z-order）是同一个数组**，所以「调照片顺序」会顺带改变谁压在谁上面。
5. 已保存后不能在页之间移动照片、合并或拆分页。

## 2. 数据模型支持情况

| 需要的信息 | 现在有没有 | 说明 |
|---|---|---|
| 照片原始拍摄时间 | ❌ 每张照片没有 | 只在创建时临时读一次（`saved[i].time`），**没有存到照片图层上**。压缩时 EXIF 已被去掉（见 `handleImageUpload` 注释），所以旧照片事后也读不回来。只有整页的 `moment.capturedAt`（这一组第一张的时间）。 |
| 照片属于哪个 Moment | ✅ | 照片图层就在 `moment.layers` 里，所属关系就是「在哪个数组里」。 |
| 照片在页内的显示顺序 | ⚠️ 间接 | 用 `moment.layers` 里视觉图层的先后。排版引擎 `layoutMoment({ visuals })` 按这个顺序放位置，但这个数组同时决定叠放顺序。 |
| Moment 的显示顺序 | ✅ | `entry.moments` 数组顺序；`moveMoment` 已有。`moment.time` 只是显示用的文字，没有任何地方按它重新排序（`pages.mjs` 只按日期排天）。 |
| 文字 / 照片说明 | ✅ | `moment.title`、照片图层 `caption`，文字图层 `captionOf` 指向照片图层 id。按图层对象移动就不会丢。 |
| Swift 模型 | ✅ 部分 | `JournalMoment` 有 `time`、`capturedAt`、`layoutEdited`、`layoutVariant`；图层有 `caption`、`captionOf`。新增字段要同步加成可选字段。 |

## 3. 最小 Schema 改动（提案，未实施）

全部是**可选字段**，旧数据不需要迁移脚本，读到没有这些字段时按现在的方式处理：

```jsonc
// 照片图层（kind: "photo"），新拍 / 新选的照片才有
{ "takenAt": "2026-11-14T10:02:00+08:00",   // 原始拍摄时间，只读、只存一次
  "takenSource": "exif" | "file" }          // 来自 EXIF 还是文件时间；没有就是不知道

// Moment
{ "photoOrder": ["layerId", "layerId", ...] } // 页内照片的显示顺序（只放照片图层 id）
```

- **不改照片本身**：不写 EXIF，不复制媒体。移动照片 = 把同一个图层对象（同一个 `mediaRef`）从一页的 `layers` 移到另一页，不新建 `media:` 记录。
- **显示顺序和拍摄时间分开**：`photoOrder` 是用户决定的顺序；`takenAt` 永远是原始时间，排序不会改它。
- **显示顺序和叠放顺序分开**：`photoOrder` 不存在时，退回「视觉图层在 `layers` 里的先后」（= 现在的行为），旧页面看起来完全一样。只有用户拖动过顺序的页才会写 `photoOrder`。
- `photoOrder` 里找不到的 id 忽略；页上有但 `photoOrder` 里没有的照片排在后面（按图层先后）。这样任何一边出错都不会丢照片。
- Moment 顺序继续用 `entry.moments` 数组，不加字段。
- 实施时同步：`Packages/LittleDaysCore/Sources/LittleDaysCore/Models.swift` 加 `takenAt`、`takenSource`（图层）和 `photoOrder`（Moment）三个可选字段，加 Core 解码测试（有 / 没有这些字段都能读、原样写回）。

## 4. 创建时：分组预览（还没保存）

**入口**：选完照片后先出现一个底部面板，三选一（不是直接生成页面）：

1. **按时间建议分组**（默认高亮，写明「建议 3 组，可以再改」）
2. **全部放在一页**
3. **自己分组**（所有照片先在一组，用户自己切开）

**建议规则（只影响「建议」）**

- 仍用拍摄时间，但不再用固定 90 分钟：在这次选的照片里找**最明显的几个时间空档**（比如比中位间隔大很多、且至少 2 小时），最多建议 4 组；少于 4 张或者都在 3 小时内，就建议一组。
- 没有拍摄时间的照片：留在它被选择时的位置，并标「无时间」；不会自己单独成组。

**分组预览页**（这时只是预览，没有写进已保存的手帐）

- 每组一张卡片：时间段（如「上午 10:02–11:45」）、照片缩略图、页数小标签。
- 两组之间有分隔线和「合并」按钮；组内照片之间点一下出现「从这里分开」。
- 长按照片可以拖动：在组内换顺序，或拖进另一组。
- 顶部：「重新建议」「全部一页」切换；底部主按钮「生成 3 页」。
- 点「生成」后才进入现在的 Quick Edit 预览（逐页看排版、写字、换排版）；最后仍是「保存」才写进手帐。
- 退出时如果做过调整，用页面内确认框问一句（沿用 `story.discard`）。

**和排版的关系**：这一页只决定「哪几张在同一页、什么顺序」。排版（照片在页上的位置、大小）在下一步，「换个排版」不会改变分组；改分组后只重新排「被改动的页」，用户手动调过的页（`layoutEdited`）不自动重排，提示「这页你调整过，要重新排版吗？」。

## 5. 已保存的手帐：移动、合并、拆分、排序

入口都在已有的地方，不新增一级页面：

| 操作 | 入口 | 行为 |
|---|---|---|
| 页面排序 | 页面目录（已有 ↑↓）+ 新增长按拖动把手 | 只改 `entry.moments` 顺序 |
| 合并两页 | 页面目录「选择」→ 勾两页或更多 →「合并」 | 后面几页的照片、文字、贴纸、录音图层按顺序接到第一页；标题：第一页有就用第一页的，其他页的标题变成文字图层放进来（不丢字）；被合并的页删除；合并后的页询问是否重新排版 |
| 拆分一页 | 页面 / 照片顺序条里点两张照片之间 →「从这里分开」 | 后面的照片（连同指向它们的说明 `captionOf`）移到紧跟其后的新页；新页 `capturedAt` 取第一张的 `takenAt`（有的话） |
| 照片移到另一页 | 选中照片 → 照片工具「移到…」→ 选目标页（或「单独成一页」） | 图层对象整个移过去，`mediaRef`、裁剪、说明不变 |
| 页内照片排序 | 照片工具「顺序」→ 底部缩略图条，长按拖动 | 写 `photoOrder`；不改叠放顺序；问是否按新顺序重新排版（不自动重排） |
| 重新排版 | 已有的「换个排版」 | 和分组无关 |

**撤销**：所有操作都走 Studio 现有的 `history`（`changeEditor` 默认会记一步），操作后出 6 秒的「已合并 · 撤销」提示（V10.47 已有带按钮的 toast）。合并 / 拆分 / 移动都是一次 `changeEditor`，撤销一步就完整回来。直到点「完成」才写进已保存的手帐（和现在一样）。

**数据安全**

- 只移动图层对象，不复制、不删除 `media:` 记录（媒体库本来就不做垃圾回收）。
- 合并时任何一页的内容都不丢：图层全部带过去，标题变文字图层。
- 失败（比如找不到目标页）就什么都不改，提示一句。

## 7. 迁移、撤销与回归测试计划

**迁移**：无迁移脚本。新字段可选；旧页面 `photoOrder` 缺省 = 图层顺序；旧照片 `takenAt` 缺省 = 未知（界面写「无时间」，退回 `moment.capturedAt` / `moment.time` 显示）。不回写旧数据，只有用户改过的页才写新字段。Swift 解码对缺字段宽容（可选）。

**撤销**：创建阶段 = 分组预览页内撤销栈（组的快照）；已保存后 = Studio `history` / `future` + 带撤销按钮的提示。

**回归测试（实施时新增 `tests/v147-browser.cjs` 起）**

1. 选 6 张跨 5 小时的合成照片 → 默认出现三选一面板，没有任何页写进已保存的手帐，草稿里也没有新页。
2. 「按时间建议」：10:00 / 11:45 在同一组（不再被 90 分钟拆开）；明显的大空档才分组。
3. 「全部一页」→ 生成 1 页；「自己分组」→ 1 组，可切开。
4. 预览中合并、拆分、拖动后点「生成」：页数和顺序与预览一致；照片说明跟着照片走。
5. 中途退出 → 确认框；取消退出时什么都没写。
6. 已保存手帐：照片 A→B 页、合并、拆分、页内排序、页面排序，各自撤销一步后 JSON 与操作前完全相同。
7. 每个操作后 `media:` 引用集合不变（不多不少），IndexedDB 媒体条数不变。
8. 旧数据（没有 `takenAt` / `photoOrder`）打开、显示、导出 PDF、备份与现在逐字节一致。
9. Reader / 日历 / 书架 / PDF 页数在合并、拆分后一致（沿用 `pages.mjs` 规则）。
10. 重启后（A2 生命周期保存）改动仍在；未点「完成」的改动按现有草稿规则保留。
11. 中英文切换不改用户写的标题、说明。
12. Swift Core：有 / 没有新字段的 JSON 都能解码并原样编码。
13. iOS 模拟器真实触摸（`tools/mac/uitest/`）：长按拖动照片排序、合并两页、撤销。

**分阶段实施建议**

- P1-a：创建时三选一 + 新的建议规则 + 分组预览（合并、拆分、拖动）。
- P1-b：已保存手帐的合并 / 拆分 / 移到另一页。
- P1-c：页内照片顺序 `photoOrder` + 长按拖动。
