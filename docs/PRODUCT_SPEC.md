# Little Days · 产品需求 V3

品牌：Little Days（手帐文具店）。

**记录生活的美好，也收藏一点点变好的自己。** / **Collect moments, grow gently.**

产品结合数字手帐、生活记录、成长追踪与未来的社交分享。界面像精品文具店，简约、温柔、有创作感；素材丰富可爱，不做成传统效率工具或普通信息流社交媒体。最终 iPhone App 是 Swift / SwiftUI 外壳（WKWebView），里面运行的就是 `Public/` 这一份 HTML/CSS/JavaScript。日常查看每次更新用**在线链接** https://claude.ai/artifact/VYUJ38K5TBqcZPB8VzJS7A （已固定在 claude.ai 侧栏；项目文件夹里双击 `Open-Little-Days.url` 也能打开）；localhost 预览只在需要录音、导出等浏览器受限功能时备用。保留 Vapor 和共享 Core。不能把网页预览称为实际运行的 SwiftUI 或真机结果。

### 封面

Minimal Linen、Vintage Leather、Floral Notebook、Pastel Cute、Travel Album、Scrapbook Collage。封面有书脊、边框/质感、标题与原创装饰，支持上传照片，而不是纯色矩形加 Emoji。

### 默认私人

新建书本和旧格式书本默认 Private；本轮 Public / Shared 选项禁用，并解释后续才提供。封面、主题或字段编辑不会发布内容。Money 默认私人；未来公开需另行确认与脱敏。

当前是单用户本机预览，私人状态**不等于已经实现服务端访问控制**。本轮没有其他账号、媒体上传 API、公开作品 API 或私信 API。

### 原生 SwiftUI 状态

保留 iOS 17+ App 工程和五页基础，新增共享 V3 模型、字体注册/选择、原创 PNG 封面及中英文设置。Core 能解码旧格式，也能保留 V3 媒体引用、字段、字体与贴纸 ID。

原生尚未实现 Web 的视频/录音导入、完整封面编辑、通用字段编辑及自由画布，也没有把浏览器 IndexedDB 数据同步到 iPhone。当前 Linux 仅验证 SwiftUI 语法，不能替代 iOS SDK 类型检查、构建、模拟器或真机测试。

## 验收与限制

- 不破坏原五页、旧字体/Emoji 图层、记录日期/ID和正文；有失败时不静默清空或重置数据。
- 视频/音频/封面/图片写入 IndexedDB 成功后才更新元数据；刷新可重开。浏览器清理站点数据或换 origin/端口仍可能失去本机资料，请导出备份。
- 备份是本地 JSON 文件（含媒体），恢复前明确确认，媒体写完后才替换元数据。大备份会使用较多内存，媒体导出上限 100 MB、导入文件上限 150 MB；尚无云备份或备份加密。
- 新媒体不写 LocalStorage；已有主照片在两处存储成功后才迁移引用。暂不自动删除被替换媒体，避免破坏撤销或恢复；媒体垃圾回收与保留策略在后续完善。
- PNG 是静态图片，不包含可播放的视频/录音，也不是完整所见即所得；长文、字体细节和主题字段的画布布局仍有限制。
- 录音需要浏览器麦克风权限，格式兼容性取决于浏览器；本轮使用 Chromium 验证，未验证 Windows 系统、iOS SDK 或真机。
- 真实多用户的私人访问、私信授权与多人原子版本冲突测试留到相应后端阶段，不用本地演示替代。

## 2026-11-11 V10.5 Captain 面板：输入、发送、关闭

- **发送**只有两种方式：点「发送」按钮，或外接键盘的 ⌘ / Ctrl + 回车。回车本身是换行。输入法正在选字（composition）时，回车、组合键和发送按钮都不发送。

- **发送中**：自己的话先进入对话，显示「正在想」气泡约 0.4 秒后出现回应；期间不能再次发送。本机回应本来是即时的，这一步是为了让用户看见「已发出」并防止连点；将来接入别的回应来源也走同一步。
- **未发送的文字**：每次输入都保存在这台设备（`little-days.keeperDraft`，不进手帐数据、不进备份）。点 ×、下拉、按 Esc、刷新页面都不会丢，也都不会发送；再次打开面板时恢复。只有成功发送后才清空。
- **关闭**：右上角 × 或下拉面板。发送后光标留在输入框（键盘不收起）。
- **没有改动**：Captain 的美术、陪伴方式、本机回应规则、两个本机流程；没有 AI、没有网络请求。
- **未验证**：真实 iPhone 的软键盘和中文输入法（无头 Chromium 里无法弹出键盘；输入法用合成的 composition 事件测试）。

## 2026-11-11 V10.6 文字格式（加粗 / 斜体 / 下划线 / 删除线）

- **在哪里可以用**：纸上的标题、正文，以及自由文字框。
- **三种用法**：① 选中几个字再点 B / I / U / S——只有这几个字变（再点一次取消；选区里只有一部分带格式时，先全部加上）。② 没有选区、只有光标时点——接下来输入的字带这个格式，再点一次关掉；光标移到别处后恢复为「跟随前一个字」。③ 选中一个文本框但没有在打字时，在「字体」面板里点——作用于整个文本框。
- **保持选区**：点格式键不会丢掉选中的文字和光标，键盘不收起。
- **组合**：四种格式可任意叠加。
- **撤销 / 重做**：每点一次格式是一步。
- **保存**：文字仍是普通文字，格式是可选的范围；保存、刷新、重新编辑后都在。以前的手帐没有格式信息，显示不变。搜索、Captain 的本机回应、首页摘要仍只读普通文字。
- **显示一致**：编辑、预览、当天阅读、书本翻页、导出的图片 / PDF 页面图一致（导出为 Canvas 绘制，换行位置可能与屏幕略有不同，这是原有差异）。
- **中文斜体**：中文字体没有真正的斜体，显示为向右倾斜；没有粗体字形的字体由系统加粗。
- **粘贴**：从别处粘贴或拖入的内容只保留文字，采用落点处的格式。
- **示例页**：设置 → 更新记录 → V10.6 下的「放一页格式示例到今天，试试看」，会在今天加一页真实可编辑的页面（一个文本框里有普通、加粗、斜体、下划线、粗体加下划线）。只有点了才添加，可随意修改或删除。
- **限制**：带时间前缀或被截短显示的标题行不能做部分格式；Safari / iPhone 上选区保持和输入法行为未实测。

## 2026-11-11 V10.7 离开 Journal Studio：完成、草稿、继续编辑

- **什么时候问**：只有点左上角返回、真的要离开编辑器时。切换封面和内页、选中文字、打开工具或预览都不会问。
- **不问就离开的两种情况**：这篇记录上什么都没写（也不会留下空草稿）；打开一篇已完成的手帐、没有做任何改动。
- **三个选择**：
  - 完成手帐——保存全部文字、照片、贴纸、布局和每一页；记录标记为「已完成」；离开编辑器。以后可以再打开编辑。不代表发布或分享。与右上角「完成」完全相同（同一个操作）。
  - 保存草稿——完整保存当前作品；记录标记为「草稿」；回到进入编辑器之前的页面。下次从离开时的那一页继续；封面、内页、图片位置、文字格式、图层都不变。
  - 继续编辑——关闭面板，留在编辑器，画布和选中状态不变。
- **Saved / Draft / Completed**：「已保存」只表示数据已经写到本机；「草稿 / 已完成」表示这篇手帐做没做完。草稿同样是已保存的。自动保存照常。
- **状态属于整篇记录**（一天：封面 + 所有内页），不属于单页；封面不是一篇独立的手帐。
- **保存失败**：不显示成功、不离开编辑器，内容留在页面上，顶部显示「保存失败」（点它可重试）。只有在保存确实不可用时，再次返回才会出现「仍然离开吗」的确认。
- **找回草稿**：首页「今天的故事 / 最近的故事」卡片、书本的页面列表、翻页、当天页面都有低调的「草稿」标签；当天页面上有「继续编辑」。
- **完成后**：与以前点「完成」一样，先看到刚收好的这一页（从阅读页进入编辑的，回到原来的阅读位置）。
- **旧数据**：以前保存的记录视为已完成；以前用返回离开、从未点「完成」的日子显示为草稿。
- **未做**：没有「单页」级别的状态；没有草稿箱式的汇总列表（草稿散见于各自的日期和书本里）；iPhone 真机未验证。

## 2026-11-11 V10.8 Captain 轻装扮（第一步）

- **目标**：让 Captain 更有个性、更像用户自己的小伙伴；不是宠物养成游戏。没有金币、签到、亲密度、等级或任何解锁——列出来的造型都可以直接选。
- **入口**：① Captain 快捷面板名字下面的一个小文字链接「装扮 ›」（轻入口）；② 设置 → Little Keeper →「角色与装扮」（管理处）。两处是同一个选择器。
- **现在有的造型**（只列有正式画稿的）：帽子——柠檬帽（默认）；小配件——毛线球（这张画里 Captain 不戴帽子）。
- **一次一个造型**：现有画稿是「整只 Captain」的成品图，帽子和配件不能分开叠加，所以目前帽子和配件共用一个选择。将来如果有分层的配件画稿，再拆成两个槽位。
- **生效范围**：首页、面板、书架旁、设置里的 Captain 一起变；选择保存在手帐数据的 `keeper.outfit`（柠檬帽存为空 = 默认），刷新后保留。
- **只有一张画的造型**：各种表情都显示这一张；首页不是「探头」，而是坐在卡片上沿。
- **还没有的**：小花夹子、毛线帽、青蛙帽、睡帽、围巾、铅笔、围裙——没有画稿，所以不出现在 App 里。Captain 只使用产品负责人提供的正式画稿，不用 SVG / CSS / 表情符号代画（V7.9 起的约定）。需要的画稿规格见 Resources/Keepers/LD-keeper-LICENSE.txt。
- **数据不存在的造型**（旧数据或手动改动）：显示默认的柠檬帽。

## 2026-11-11 V10.9 Captain's Corner：聊天修正与三个入口

- **聊天理解**（本机规则，见 docs/KEEPER_AI_PLAN.md 第 11 节）：社交表达（问候、早安 / 晚安、夸奖、夸帽子、谢谢、关心、摸摸 / 抱抱、想玩）有各自的回应；关于今天的话区分写完了、打算写、还没写，以及累 / 难过 / 开心；只有问「你会做什么」才介绍功能；听不懂时诚实地说没太懂。每种回应有 2–3 句，近期用过的不重复。回应跟随界面语言。
