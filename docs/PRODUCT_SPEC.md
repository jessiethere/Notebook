# Little Days · 产品需求 V3

品牌：Little Days（手帐文具店）。

**记录生活的美好，也收藏一点点变好的自己。** / **Collect moments, grow gently.**

产品结合数字手帐、生活记录、成长追踪与未来的社交分享。界面像精品文具店，简约、温柔、有创作感；素材丰富可爱，不做成传统效率工具或普通信息流社交媒体。最终 iPhone App 是 Swift / SwiftUI 外壳（WKWebView），里面运行的就是 `Public/` 这一份 HTML/CSS/JavaScript。日常查看每次更新用**在线链接** https://claude.ai/artifact/VYUJ38K5TBqcZPB8VzJS7A （已固定在 claude.ai 侧栏；项目文件夹里双击 `Open-Little-Days.url` 也能打开）；localhost 预览只在需要录音、导出等浏览器受限功能时备用。保留 Vapor 和共享 Core。不能把网页预览称为实际运行的 SwiftUI 或真机结果。

### 封面

Minimal Linen、Vintage Leather、Floral Notebook、Pastel Cute、Travel Album、Scrapbook Collage。封面有书脊、边框/质感、标题与原创装饰，支持上传照片，而不是纯色矩形加 Emoji。

### 默认私人

新建书本和旧格式书本默认 Private；本轮 Public / Shared 选项禁用，并解释后续才提供。封面、主题或字段编辑不会发布内容。Money 默认私人；未来公开需另行确认与脱敏。

当前是单用户本机预览，私人状态**不等于已经实现服务端访问控制**。本轮没有其他账号、媒体上传 API、公开作品 API 或私信 API。

### 原生 SwiftUI 状态

保留 iOS 17+ App 工程和五页基础，新增共享 V3 模型、字体注册/选择、原创 PNG 封面及中英文设置。Core 能解码旧格式，也能保留 V3 媒体引用、字段、字体与贴纸 ID。

原生尚未实现 Web 的视频/录音导入、完整封面编辑、通用字段编辑及自由画布，也没有把浏览器 IndexedDB 数据同步到 iPhone。当前 Linux 仅验证 SwiftUI 语法，不能替代 iOS SDK 类型检查、构建、模拟器或真机测试。

## 完整 V3 目标与后续阶段

### Journal Studio 多媒体创作

- Photo：多照片拼贴、自由裁切/拖动/缩放/旋转、相框、滤镜、边框。
- Video：视频卡片、封面与播放，后续基础剪辑、裁切。
- Audio：录制/上传、设计感播放器、进度/时长，语音转文字为可选后续能力。
- Text：标题、正文、手写注释、多文字框，独立字体/大小/颜色/粗细/字距/对齐与位置。
- 素材：原创/授权贴纸、便签、标签、胶带、相框、日期/地点/心情/天气/成长信息卡片；统一图层、撤销/重做。
- Music：页或书本可选背景音乐，播放/暂停/音量/循环；与视频/录音协调降低音量或暂停。只使用原创、明确授权或用户有权使用的音频；不抓取 Spotify/Apple Music/YouTube 歌曲，公开传播需相应授权。

字体类别包括 Elegant Serif、Handwritten、Cute Rounded、Vintage、Minimal Sans、Decorative、Chinese Fonts。每个文件的来源、商业使用与再分发许可证保留在共享资源和 [ASSETS.md](ASSETS.md)。

贴纸库覆盖 Cute Animals、Flowers & Nature、Food & Drinks、Travel、Fitness、Beauty & Skincare、Study & Reading、Washi Tapes、Frames & Labels、Seasonal Collections。未来允许自建贴纸包。

### My Books 与主题记录

任意主题、描述、类别、封面照片/背景/颜色/字体/装饰/书脊/边框/质感、基础模板或空白书本。以通用字段系统扩展 Fitness、Recipe、Learning、Money、Skincare，以及植物、宠物、关系、婚礼、电影等任意主题，避免重复写编辑器。

成长记录按同一个日期/记录 ID 关联日历与手帐，不复制输入。未来将主题字段制作成可自由排版的信息卡片。

### Community 与公开发布

Discover / Following / Popular / Categories / Search；个人主页；点赞、评论/回复、收藏、分享、关注、举报；可关闭评论或撤回为私人。热门排序按本周/本月，考虑互动和发布时间。

公开前必须确认具体页面与所有媒体，不自动公开消费、照片或录音。收藏是引用与收藏状态，复制编辑是另一种授权行为，必须遵守作者许可和保留来源。允许收藏作品、模板、食谱、封面灵感与公开素材包。

### Friends 与 Direct Messages

Follow 是单向公开内容关注；Friends 需申请/接受/拒绝的双向关系。支持搜索、列表、取消、屏蔽、举报；好友关系不授予私人手帐访问权。

私信包括一对一文本、公开作品链接、表情/贴纸、时间、未读、自己的消息/会话删除、屏蔽/举报。图片/语音/群聊为后续。Phase 2 只做明确标记的虚拟好友/模拟消息；真实私信须有账号、服务端存储、成员访问控制和反骚扰机制。

### Collaborative Journal

Couple Journal、Travel Together、Best Friends Book、Family Memories、Shared Recipe Book、Fitness Buddies。邀请授权成员添加/编辑页面与媒体，标记创建者/编辑者，按日期回看。

Owner 管理成员和共享；Editor 编辑授权内容；Viewer 查看和评论。移除/退出后撤销后续访问。协作默认仅成员可见，公开需明确的共同授权，不能由一个成员擅自发布他人私人内容。

先逐页保存 + 版本检测/冲突提示 + 最近版本恢复，再探索实时光标、共同画布与评论标注。本轮本机标签页检测不代表已实现多人协作。

2026-11-08 本机演示（“演示 · 未联网”）：在手帐本详情中可折叠显示；只能邀请好友且好友本身不是成员；Editor/Viewer 与模拟接受/退出、移出（保留并标注其页面）；贡献者标记；每次改动一个版本，恢复需确认且不丢当前内容；模拟同时编辑时两份文字都保留，由拥有者选择；公开需全部成员同意（未开放）。数据只存在演示存储，不进入私人手帐。

### 后端与隐私

复用 Vapor 评估账号/认证、个人主页、公开作品与互动、关注/好友、私信权限、协作角色、媒体对象存储、屏蔽/举报/管理、删除与恢复。建议模型和访问矩阵见 [ARCHITECTURE.md](ARCHITECTURE.md)，均为后续设计，未部署。

禁止将真实用户记录、媒体、密钥或备份提交到公开 GitHub。仓库只包含公开示例、原创/授权资源和生成的测试资料。

## 验收与限制

- 不破坏原五页、旧字体/Emoji 图层、记录日期/ID和正文；有失败时不静默清空或重置数据。
- 视频/音频/封面/图片写入 IndexedDB 成功后才更新元数据；刷新可重开。浏览器清理站点数据或换 origin/端口仍可能失去本机资料，请导出备份。
- 备份是本地 JSON 文件（含媒体），恢复前明确确认，媒体写完后才替换元数据。大备份会使用较多内存，媒体导出上限 100 MB、导入文件上限 150 MB；尚无云备份或备份加密。
- 新媒体不写 LocalStorage；已有主照片在两处存储成功后才迁移引用。暂不自动删除被替换媒体，避免破坏撤销或恢复；媒体垃圾回收与保留策略在后续完善。
- PNG 是静态图片，不包含可播放的视频/录音，也不是完整所见即所得；长文、字体细节和主题字段的画布布局仍有限制。
- 录音需要浏览器麦克风权限，格式兼容性取决于浏览器；本轮使用 Chromium 验证，未验证 Windows 系统、iOS SDK 或真机。
- 真实多用户的私人访问、私信授权与多人原子版本冲突测试留到相应后端阶段，不用本地演示替代。
