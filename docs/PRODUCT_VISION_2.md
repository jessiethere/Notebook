## 2. 产品架构（Vision 2.0）

围绕四件事，不新增导航：

| 部分 | 作用 |
| --- | --- |
| **Today（首页）** | 今天想记什么、今天的几页、那年今天、今天要做的事 |
| **Calendar（日历）** | 按日期回看、补记、搜索 |
| **My Books（书架）** | 我的手帐本与收藏（标签、翻书、分享 PDF） |
| **Journal Studio** | 写一页的创作体验（照片 + 一句话、随手写、手绘、自由排版、Quick Create 故事），从 ＋ 和各处进入，不一定是单独的 tab |

**不重新引入独立 Growth 模块**，不做成长仪表盘。

## 3. Little Keeper：Grow Through Living

> **用户不需要追踪自己的成长；他们记录下的生活，会自然地塑造 Little Keeper 的小世界。**
> 想要的感受：「我在收集我的生活，我的小伙伴在陪我一起长大。」

- Little Keeper 是一个**可选**的小伙伴，用来让记录更温暖，而不是多一件事。
- 用户从不需要「为了喂它 / 照顾它 / 让它开心」去写日记。没有饥饿、心情下降、生病、离家出走。
- 没有每日任务，没有连续天数惩罚，没有过期或衰减。
- 可以完全忽略，也可以在设置里关掉；关掉不影响任何记录。

### 3.1 伙伴成长（从现有的记录行为派生）

成长**只来自已经存在的行为**，不新建任何追踪：

- 写了一页（照片 + 一句话、随手写、手绘、故事）
- 记下一个有意义的时刻（一天里的一页 Moment）
- 放进照片和故事
- 在 My Books 里把记录收进一本手帐本、整理书架（标签、排序）
- 回看和整理（打开「那年今天」、翻书、搜索并打开一页）

公平规则（防止「奖励长度 / 正能量 / 刷量」）：

- **以「天」计，不以字数、页数或照片张数计**：同一天里，每一类行为最多算一次（例如「今天写过」「今天回看过」），写 3 页和写 1 页一样。
- **不读情绪**：开心、难过、普通的一天完全一样；不做情感分析。
- **不给连续奖励**，也不对中断做惩罚；隔了一个月再回来，成长继续，不会掉。
- 成长是缓慢的阶段（例如 种子 → 小芽 → 小叶 → 花苞），没有数字排行，也没有「还差 N 经验」的催促。

### 3.2 故事里的小世界（收藏品）

Little Keeper 有一个小房间 / 小角落。里面的物件**代表真实的记忆**，不是随机掉落的游戏奖励。每件物件都能点开，看到「它来自哪一天、哪一本手帐」。

**来源只用元数据**：日期、页面类型、手帐本的类别 / 标签、某本书的页数、是否回看过。**从不读取或上传正文**，不需要把私人文字交给任何 AI 服务，全部在设备上按规则计算。

MVP 只做少量例子（因为没有习惯 / 健身 / 学习追踪器，全部从 My Books 和页面派生）：

| 物件 | 规则（MVP） | 象征 |
| --- | --- | --- |
| 明信片 | 类别为 Travel 或带 #旅行 标签的手帐本里有了第一页 | 一段旅行记忆 |
| 书架上的一本小书 | 带 #阅读 / #学习 标签的手帐本里有了第一页 | 读过、学过的东西 |
| 小相框 | 第一次从「那年今天」打开往年的一天 | 重温过去 |
| 书签 | 任意一本手帐本攒满 10 页 | 一本慢慢写满的书 |

之后可以按同样的方式加：运动类手帐（#运动）→ 小球鞋；创作类（手绘页面）→ 一盒彩色铅笔；反思类（随手写页面）→ 小信封。都是同一种数据结构，只加定义，不加新追踪。

## 4. 可扩展的数据模型（提案）

原则：**成长和收藏尽量从现有数据派生**，只存用户自己的选择，避免第二套「真相」。

```jsonc
// library.json（共享资源，像 kits / music 一样）
"keeperCollectibles": [
  {
    "id": "postcard",
    "nameZh": "明信片", "nameEn": "Postcard",
    "art": "keeper/postcard.svg",          // 原创素材，带许可证说明
    "symbolZh": "一段旅行记忆",
    "rule": { "type": "first-page-in-book", "bookCategory": ["Travel"], "bookTag": ["旅行", "travel"] }
  },
  { "id": "little-book", "rule": { "type": "first-page-in-book", "bookTag": ["阅读", "学习", "reading"] } },
  { "id": "photo-frame", "rule": { "type": "revisited-memory" } },
  { "id": "bookmark",    "rule": { "type": "pages-in-book", "min": 10 } }
]
```

```jsonc
// little-days.v1 里新增的可选字段（旧数据没有它也能正常打开）
"keeper": {
  "enabled": false,                 // 默认关；第一次只轻轻邀请一次
  "name": "",                       // 用户可以给它起名
  "unlocked": [                     // 只存「哪天、来自哪里」的引用，不存正文
    { "id": "postcard", "at": "2026-11-12", "sourceDate": "2026-11-12", "sourceBookId": "travel" }
  ],
  "placed": ["postcard"],           // 摆在小房间里的物件（用户可收起）
  "revisitedOn": ["2026-11-10"]     // 唯一需要记录的新行为：打开过「那年今天」的日子
}
```

- 规则引擎：一个纯函数 `keeperState(state, catalog)` → `{ stage, newlyUnlocked }`，在保存后计算；和 search.mjs 一样放在 `Public/js/keeper.mjs`，Node 测试。
- 阶段 `stage` 由「记录过的不同天数 + 有记录的不同手帐本数 + 回看过的天数」按天去重计算，不存数字。
- Swift：`Models.swift` 加可选的 `KeeperState`，Core 测试解码旧数据和新数据。
- 备份 / 恢复自动包含（在 `little-days.v1` 里）；隐私开关「首页隐藏今天的内容」打开时，首页不显示新物件的来源。

## 5. 体验位置（不新增导航）

- **首页**：一个很小的入口（Little Keeper 的小角落缩略图），可以在设置里隐藏。
- **书架**：在「我的习惯」旁边放一本「Little Keeper 的小房间」（与现有书的形式一致）。
- **获得新物件时**：保存后在翻书页上方轻轻出现一次「Little Keeper 收到了一张明信片 · 来自 11 月 12 日」，可以关掉；不弹窗打断写作。

## 6. MVP 范围与不做的事

- MVP：开关 + 4 个物件 + 4 个成长阶段 + 小房间页面。
- **不做**：习惯 / 健身 / 学习追踪器、成长仪表盘、每日任务、连续天数奖励或惩罚、宠物照顾（喂食 / 心情 / 生病）、按字数或正能量给奖励、任何把正文发给 AI 的功能、社交比较或排行。

## 7. 需要用户批准 / 决定的事

1. **是否开始实现 MVP**（第 6 节范围）。
2. **「我的习惯」怎么处理**：保留现状、收进实验室，还是停止新建、只保留已有数据可读？现有数据都会保留。
3. **实验室的旧等级 / 经验值**：并入 Little Keeper 的成长阶段，还是移除？
4. **默认开关**：默认关、第一次轻轻邀请一次（建议），还是默认开？
5. **形象与小房间的美术方向**（原创素材，需要设计稿）。
