## 0. 结论先说

1. **真正值得押注的不是「功能多」，而是一个体验：选今天的照片 → 1 分钟内得到一套你愿意保存的手账页 → 它们自动收进一本可以翻、可以给家人看的书。** 单看每一块（拼贴、日记、相册书），竞品都有；把它们连成「不用设计」的一条路，才是还没被做好的地方。这一点**还没验证**。
2. 现在的 Quick Create 已经完成了一半 **[事实]**：选多张自己的照片 → 按照片形状自动排（不裁切）→ 换一种 / 写一句 / 配乐 / 分享 → 保存，最少约 4 次点击加选照片。缺的是：**一天多个 Moment 一次做完**、**页面之间有层次（封面 + 章节）**、**统一的配色字体装饰**、**手动调整后不被重排覆盖**。
3. 下一轮只做三件事（见 §7、§9）：**① 一次做完一天的多 Moment Quick Create；② 排版引擎 v2（模板 + 主题套装 + 文字适配）；③ 自动与手动共存（钉住手动调整）**。其他全部暂停扩展。

## 1. 仓库现状检查 **[事实]**

| 部分 | 现状 | 对本方案的意义 |
|---|---|---|
| 入口 | 底部 ＋ → 底部面板：照片 + 一句话 / 随手写 / 手绘；照片来源（我的照片 / 今日推荐 / 照片库）；选书；都记住上次选择 | 入口已短；但**要先在三种方式里选**，且一次只做一页 |
| 照片导入 | `imageBlob()` 把原图缩到最长边 1200px 再用 canvas 重新编码 JPEG，存 IndexedDB | **重新编码会丢掉 EXIF 拍摄时间**；按时间分组必须在缩图前读 |
| 自动排版 | `smart-layout.mjs`：按宽高比的「整齐行」排版，3 种样子（clean / scrapbook / hero），保证不裁切、不重叠；纯函数，有单元测试 | 是排版引擎 v2 的地基，可直接扩展 |
| 快速结果页 | 换一种（3 种）/ 写一句（只有一行标题）/ 配乐 / 分享 Story / 编辑 / 完成 | 结构可复用；**正文不参与排版** |
| 数据模型 | 一天 = `entry`（封面）+ `moments[]`（每页）；页面有 `layers`（照片 / 文字 / 贴纸 / 音视频）、`layoutTemplate`、`layoutVariant`、`layoutEdited`、`backdrop`、`textStyle`、`music`；`bookId` 单值；结构化字段 `fieldValues` 挂在**一天**上 | 「一天多 Moment」已有模型；**同一条内容进多本书、结构化字段按页记录**还不支持 |
| 自由编辑 | Studio：拖动、双指缩放旋转、角上把手、图层条、文字样式条、撤销 / 重做、草稿自动保存、浮动保存 | Quick 与 Creative **本来就共用同一份 `layers`**；缺的是对齐吸附和「重排不覆盖手动」 |
| 阅读 | 日历阅读一天、书的列表 / 翻页阅读、就地编辑、整本书 PDF、背景音乐 | 预览和保存后阅读可以直接复用翻页组件 |
| 原生 | Swift 外壳（SwiftUI + WKWebView）运行同一份 `Public/`；Swift Core 有可选字段模型；Vapor 保留；**没有 PhotoKit 桥接** | 「今天拍的照片」自动出现、拍摄时间可靠，需要原生桥接（F6） |
| 规模 | `Public/app.js` 5,911 行（单文件） | 新功能应放在新的纯模块里，不再往 app.js 堆 |
| 验证数据 | 只有本机测试日志（`events.mjs`，不含内容）；**没有任何真实用户数据** | 所有「好用 / 好看」都还是假设 |

## 2. 竞品判断的独立检查

| 你的判断 | 我的检查 | 结论 |
|---|---|---|
| Zinnia 偏精细创作 | 基本成立：贴纸、模板、Planner、主题素材包，核心是「手做」**[事实，见 STRATEGY.md]**。但它也有模板，「快速好看」不是空白 | 「比 Zinnia 快」**值得验证**，但不能说它做不到 |
| Day One 强在记录与回忆 | 成立；Shared Journals 已免费 **[事实]**；页面是信息流式，不是拼贴 | 「共同记录」不是差异；「页面好看」是差异 |
| Shuffles 偏拼贴分享 | 成立；热度下降 **[事实]**，说明「一张好看的拼贴」留不住人 | 我们必须把单页连成**连续的书**，否则会重复 Shuffles 的路 |
| （你没提）Apple Journal | iOS 自带、免费，会根据照片 / 运动 / 地点**建议**今天写什么 **[事实]** | 「零操作开始」它更强；我们只能在「成品好看 + 成书」上赢 |
| （你没提）My Diary 等可爱日记 App | 文字为主 + 照片附件 + 贴纸 + 心情 + 锁，规模大 **[事实，STRATEGY.md]** | 「可爱日记」是标配，不能当差异 |
| （你没提）Instagram Layout / CapCut / Canva 模板 | 美国用户做「photo dump」的现成工具 **[假设]** | 真正的对手是「随手发个 Story」，而不是另一个手账 App |
| （你没提）相册书服务（Chatbooks、Artifact Uprising 等）、相册「回忆」 | 照片自动成书 / 回忆视频已存在 **[事实，名称层面]**；Day One 是否仍提供打印成书 **[待核实]** | 「成书」本身也不独特；独特的是**每天顺手记、自动长成书** |

**已经被覆盖的**：可爱贴纸字体、多媒体日记、共同记录、单张拼贴、自动回忆视频。
**还值得验证的**：①普通人 90 秒内做出「像手做的」一页（不是网格拼图）；②一天多个 Moment 自动有层次；③这些页自动积累成主题书，并且愿意反复翻、给家人看。

## 3. 产品定位

**一句英文**：*Pick today's photos — Little Days turns them into a scrapbook page you'll love in a minute, and your days into a book.*

更短的 App Store 副标题备选：*Scrapbook your day in a minute.*

**真正值得验证的优势**（按重要性）：

1. **Beautiful by default**：不选模板、不学排版，第一次生成的页面就愿意保存（对比 Zinnia 的手做、Day One 的信息流）。
2. **Day story, not a collage**：一天的几个 Moment 自动变成「封面 + 章节」，而不是一张塞满的拼图（对比 Shuffles / Layout）。
3. **Days become a book**：每页自动收进书，像书一样翻、配音乐、给家人看（对比 My Diary、Apple Journal 的列表）。

## 4. 核心用户画像（**全部是假设**）

| 画像 | 描述 | 为什么会用 | 最大的不确定 |
|---|---|---|---|
| A. 爱拍照的日常记录者（主力） | 美国 20–35 岁，每天拍 10–50 张（咖啡、饭、天空、宠物），会发 Stories，收藏 #journalwithme / scrapbook 内容，但自己没时间做 | 想要「好看的回忆」，不想当设计师 | 她可能觉得发 Stories 就够了 |
| B. 兴趣 / 进步记录者 | 健身、做饭、护肤、学习；想看到自己的变化 | 主题书 + 一点结构化字段 + 时间轴 | 可能更习惯用专门 App（Strong、Notion） |
| C. 家庭记忆管理者（以后） | 父母记孩子、情侣记共同生活，一个人记、家人看 | 整本书 PDF / 翻页给家人 | 共同创作需求要先测，不先开发 |

**不做的人**：专业手账玩家（Zinnia / GoodNotes 用户）、纯文字日记作者（Day One 用户）。

## 5. Quick Create 用户旅程

设计稿对应：①Main → ②Pick → ③Moments → ④Preview → ⑤Creative → ⑥Reader。

| 步骤 | 页面 | 主要按钮 | 必须的操作 | 目标耗时 |
|---|---|---|---|---|
| 0 打开 App | 首页「今天」卡片：大问题「今天有什么值得记录？」；今天的照片缩略图（原生：PhotoKit 自动找出今天拍的；网页：空位） | 「用今天的 N 张照片」/「只写几句」/「录一段声音」 | 0 | 2 秒 |
| 1 选照片 | 原生：今天的照片已全选，点掉不要的；网页：系统多选（可排序） | 「添加」 | 1 + 选 N 张 | 10–20 秒 |
| 2 自动分 Moment | ② 按拍摄时间自动分组（相隔 > 90 分钟就分开），每组一张卡；长按拖动照片换组 | 「下一步」/「直接排版」 | 0（可跳过） | 5 秒 |
| 3 每个 Moment 写一句 | ③ 每组一行输入、语音按钮、按书提示的小字段（如「深蹲 60kg × 5」）、「也放进 Fitness Journal」 | 「排成今天的故事」/「跳过」 | 0–3 句 | 20–40 秒 |
| 4 自动排版预览 | ④ 封面（时间线）+ 每个 Moment 一页；页标签切换；版式、配色、「↻ 换一种」 | 「保存」/「自己调整」 | 1 | 10–20 秒 |
| 5 保存 | 落到 ⑥ 书的翻页阅读，提示「已收进这本书 · 也放进 Fitness Journal」 | 「✎ 编辑这页」/「发 Story」/「给家人看」 | 0 | 2 秒 |
| 之后 | 日历当天有标记；书架里的书多了几页 | — | — | — |

**最短路径**：＋ → 添加 → 直接排版 → 保存 = **3 次点击 + 选照片**，目标 30–45 秒。**写一句的完整路径**目标 60–90 秒（设计目标，未验证）。

**不强迫的东西**：不先选主题 / 模板 / 字体 / 手帐本。书默认放进「每天」那本（或上次用的），主题书只在 ③ 用一个勾选提示。

**一个 Moment 也可以**：只选了一组照片时跳过 ② ③ 的分组，直接得到一页（等于现在的流程）。

## 6. 高保真 iPhone 界面（见设计稿）

视觉保持现有：奶油白 `#F8F5EF`、纸 `#FFFDFA`、鼠尾草绿（按钮用加深的 `#5F6F52`，保证白字对比度）、柔粉 `#E8CFCF`、奶油黄 `#F3E7B3`、墨色 `#2F2A26`；标题 Noto Sans SC，英文装饰 Cormorant Garamond 斜体，手写 Caveat。

1. **Quick Create 入口（①）**：首页最上面一张大卡片，只问一个问题；主按钮占满宽度、在拇指区；下面是「今天已经记下的」小页面和「再加一个 Moment」。底部导航建议变成 4 个（今天 / 日历 / ＋ / 我的书），这和任务 G 的「成长合并」一致。
2. **多照片选择与排序（②）**：按时间分好的组，每组时间标签用不同柔色；组之间是「在这里分开」虚线；长按拖动（拖动中有描边和标签）。
3. **多 Moments 编辑（③）**：当前组展开，其他组收成一行；一句话输入框、语音按钮、结构化小字段以「＋ 时长」「＋ 感受」的胶囊出现（不是表单）；「也放进 Fitness Journal」一个勾。
4. **自动排版预览（④）**：封面是「时间线」版式（时间、照片、一句话，左右交错，胶带和手写标题）；上面有页标签，下面是版式、配色和「↻ 换一种」；右上角就是「保存」。
5. **Creative Mode 入口（⑤）**：同一页直接变成可编辑；选中照片四角把手在内侧；靠近中线出现粉色虚线和「居中对齐」；选中时出现黑色上下文工具条；底部 5 个工具（照片 / 文字 / 贴纸 / 纸张 / 更多），高级功能都在「更多」里；页面角上提示「已手动调整 · 换版式时保留」。
6. **保存后阅读页（⑥）**：书的翻页视图，音乐胶囊，「✎ 编辑这页 / 发 Story / 给家人看」三个动作，底部提示保存到了哪里。

## 7. Auto Layout 设计（规则式，不依赖生成式 AI）

### 7.1 模板（7 个）与选择条件

| 模板 | 适用条件 | 排法 | 已有基础 |
|---|---|---|---|
| T1 时间线 Timeline（封面） | 一天 ≥ 2 个 Moment | 每个 Moment 一行：代表照片（组里第一张，横图优先）+ 时间 + 一句话，左右交错；> 4 个 Moment 时每行缩小，> 6 个只放前 5 个加「还有 N 个」 | 新 |
| T2 主角大图 Hero | 1 张照片，或某张明显最好（用户标星） | 照片按原比例尽量大，标题条压在下缘 | `smart` hero（不裁切） |
| T3 整齐拼贴 Clean | 2–6 张照片 | 按宽高比分行，等高、填满宽度、不裁切 | `smart` clean |
| T4 手账拼贴 Scrapbook | 2–5 张照片 | 相框 + 小倾斜 + 胶带 + 手写标题；最多 2 个装饰 | `smart` scrapbook |
| T5 胶片条 Film strip | 3–8 张、宽高比相近（如一桌菜） | 一条或两条胶片格，等宽，标题在下 | 新 |
| T6 文字卡 Note | 0–1 张照片 + 正文 ≥ 60 字 | 正文为主（首字放大），照片像贴进去的拍立得 | `text` 页 + 照片层 |
| T7 杂志 Magazine | 1 张竖图 + 有标题 | 大衬线标题与竖图并排，像杂志内页 | 新（借用杂志封面字体） |

**选择规则**（按顺序判断，可被用户「换一种」轮换到下一个合适的）：
1. 这是封面且 Moment ≥ 2 → T1。
2. 正文 ≥ 60 字 → T6。
3. 照片 = 1 → 竖图且有标题 → T7，否则 T2。
4. 照片 3–8 且宽高比差异 < 25% → T5 作为候选之一。
5. 其余 → T3 / T4 / T2-hero 轮换（现在的三种样子）。

### 7.2 不同宽高比
- 沿用 `safeAspect`（限制在 0.3–3.5）和「整齐行」算法，**默认不裁切**；只有带相框的 T4 允许 ≤ 8% 裁切。
- 全景（> 2.2）单独占一行；很长的竖图（< 0.5）单独占一列，其他照片在旁边排成一列。
- 视频按自己的宽高比参与排版，封面帧 + ▶ 角标；音频是一张固定 3:1 的「票根」卡片，放在剩余空间最大的位置。

### 7.3 多段文字
- 一句话（≤ 70 字）放在标题条；正文按 T6 排；Moment 的标签以小胶囊放在时间旁边。
- **文字适配**：排版引擎用 canvas `measureText` 先量，字号按 18 → 16 → 14px 逐级缩小、限制行数；还放不下时，**多余的正文不硬塞**，而是放在阅读页的页面下方（现在的 `pageBody` 已经这样显示），页面上显示「…」。绝不悄悄截断。
- 封面时间线里每行最多 2 行字。

### 7.4 主题套装（统一字体、配色、装饰）
- 新增 4–6 个「套装」（library.json `kits`）：纸张、主色、标题字体、正文字体、手写字体、胶带颜色、可用装饰（≤ 6 个原创贴纸）。
- **一天的所有页用同一个套装**，所以看起来是一套。默认跟书的封面颜色走；预览里的色点可以换。
- 进阶（P1）：从照片里取主色（缩成 16×16 求平均 / 主色），选最接近的套装。
- **装饰规则**：每页最多 2 个；只放在排版后计算出的空白角落（与照片和文字的外框不相交）；封面多一条胶带。

### 7.5 用户手动修改后如何保护
- Creative Mode 里移动 / 缩放 / 旋转过的图层标记 `pinned: true`，页面 `layoutEdited: true`（字段已存在）。
- 「↻ 换一种」只重排**没被钉住**的图层，钉住的位置当作障碍物避开；按钮文字变成「换一种（保留你调过的）」，另有「全部重新排」需要确认。
- 任何重排都进撤销历史；旧页面只有用户主动点才会重排，**打开旧页永远不自动改动**。

## 8. 技术实现方案（在现有架构上最小增量）

**不改技术栈、不重写**：继续 Swift 外壳 + `Public/` 一份 Web 界面 + Swift Core + Vapor（不动）+ IndexedDB 存媒体。

### 8.1 新的纯模块（可单元测试，不碰 DOM）
- `Public/js/day-story.mjs`：`groupByTime(photos, gapMinutes = 90)`、`chooseTemplate(moment)`、`timelineCover(moments, kit)`、`decorate(slots, kit)`。
- `Public/js/exif.mjs`：约 80 行的 JPEG APP1 解析，只读 `DateTimeOriginal`；读不到就用 `file.lastModified`，再不行用选择顺序。**必须在 `imageBlob()` 缩图之前调用**。
- `smart-layout.mjs` 扩展：T5 / T7、障碍物（钉住的图层）、文字框量测接口。

### 8.2 界面（复用现有组件）
| 新屏 | 复用 |
|---|---|
| ① 今天卡片 | 首页现有卡片和「今天已记」逻辑、`quick` 状态 |
| ② 分组确认 | `#choose-dialog` 底部面板样式、书架拖动排序的手势代码 |
| ③ 每组一句 | 快速结果页的「写一句」、录音、书的 `fields` / `recordTemplates` |
| ④ 预览 | 书的翻页阅读组件（`flipBookHTML`）、配乐面板、Story 导出 |
| ⑤ Creative | 现有 Studio（把手、图层条、文字样式条、撤销重做）+ 新增吸附线 |
| ⑥ 阅读 | 已有翻页阅读、就地编辑（`readReturn`）、整本书 PDF |

### 8.3 数据结构（全部可选字段，schemaVersion 仍为 1，无需迁移）
- 页面（moment）：`capturedAt`（ISO 时间）、`kit`（套装 id）、`alsoIn: [bookId]`（也出现在哪些主题书）、`habitId`（关联打卡）、`fieldValues`（按页的结构化字段，旧的按天字段继续读）。
- 图层：`pinned: true`。
- 一天（entry）：封面 `layoutTemplate: "timeline"`、`storyKit`。
- 安全规则：自动生成封面**只在封面为空时**写入；已有内容一律不覆盖；旧数据没有这些字段时按现在的行为显示。
- 同步改 `Packages/LittleDaysCore` 的 `Models.swift`（可选字段）和 CoreTests。

### 8.4 草稿与恢复
- Quick 流程每一步写入本机 `little-days.quick-draft`（只存 id 和文字，照片已在 IndexedDB）；首页显示「继续上次没做完的故事」。

### 8.5 原生（F6，P1）
- PhotoKit 桥接（`WKScriptMessageHandler`）：返回今天的照片（缩略图 + `creationDate`），解决「今天的照片自动出现」和拍摄时间可靠性；PHPicker 支持有序多选。
- 触感反馈：拖动吸附、保存时轻震。

### 8.6 风险
| 类型 | 风险 | 对策 |
|---|---|---|
| 技术 | 网页上 iOS 照片的 EXIF 时间可能缺失（HEIC 转 JPEG、隐私处理）**[待核实]** | 读不到就按选择顺序；原生用 PhotoKit |
| 技术 | 20+ 张原图在 WKWebView 里内存紧张 | 逐张缩图（已是 1200px），排版只用宽高比 |
| 技术 | `app.js` 太大，改动互相影响 | 新逻辑进纯模块；app.js 只做接线 |
| 数据 | 重排误动旧页面 / 覆盖封面 | 只在用户主动操作时重排；封面非空不写；导入导出与备份测试 |
| 产品 | 自动分组分错，用户困惑 | 分组页可跳过、可拖动；默认 90 分钟阈值，测试中调 |
| 产品 | 多了 ② ③ 两步反而变慢 | 两步都可跳过（「直接排版」），测平均点击数 |
| 产品 | 「好看」主观 | 用真实用户的照片测，不用示例图 |

### 8.7 测试重点
- 排版纯函数：不重叠、在页面内、不裁切（T4 ≤ 8%）、文字不溢出、同输入同输出、钉住的图层不动。
- 分组：边界时间、同一分钟多张、没有时间信息。
- E2E：从 ＋ 到保存的点击数、草稿恢复、旧数据打开不变、备份恢复后新字段保留。
- Swift Core：新可选字段解码；旧 JSON 照常解码。
- 性能：20 张照片从选到预览 < 5 秒（中端 iPhone，原生时测）。

## 10. 用户验证方案（15–20 人）

**招募**：美国 18–35 岁，每天拍照 ≥ 10 张、近 3 个月没用过手账 App 但收藏过手账 / scrapbook 内容；排除专业手账玩家。用 TestFlight 或手机打开固定链接。

**第 1 天：远程主持 30 分钟（只观察，不帮忙）**
1. 不给教程：「用你今天手机里的照片，记录今天。」→ 计时到第一次保存。
2. 让她再用 Creative Mode 改一处自己不满意的地方。
3. 对比：同一组照片用 Instagram Layout 或 Apple Journal 做一次，问「哪一个你更想留着？」
4. 问卷：满意度 1–5、会不会保存 / 分享、哪里卡住。

**第 1–14 天：自然使用**（本机日志 + 第 7、14 天各一次 5 分钟问卷）

**指标与继续的门槛（我们自定的，不是行业标准）**

| 指标 | 怎么量 | 继续 | 需要改 | 重新考虑 |
|---|---|---|---|---|
| 第一次完成时间 | 打开到保存 | 中位数 ≤ 90 秒 | 90–180 秒 | > 180 秒 |
| 是否需要帮助 | 主持人介入次数 | ≤ 20% 的人需要 | 20–40% | > 40% |
| 作品满意度 | 1–5 分 | 中位 ≥ 4 | 3.5–4 | < 3.5 |
| 保存 / 分享 | 保存率；7 天内导出或分享的人 | 保存 ≥ 80%，分享 ≥ 40% | — | 分享 < 20% |
| 主动再用 | 14 天内 ≥ 3 个不同日子做页 | ≥ 40% 的人 | 25–40% | < 25% |
| Quick vs Creative | 生成后打开 Creative 的比例、改了什么 | < 40% 打开且改得少 | 40–60% | > 60%（说明自动排版不够好） |
| 对比竞品 | 「更想留着哪个」 | ≥ 60% 选 Little Days | 40–60% | < 40% |

**新增本机事件**（不含内容）：`story_start`、`moments_count`、`grouping_edited`、`regenerate`、`creative_open`、`pinned_edit`、`story_saved`、`share`。

**判读**：时间 + 满意度 + 再用三项都过 → 继续投入；满意度过但再用低、而且记录集中在少数特别的日子 → 转向「旅行 / 里程碑书」（STRATEGY.md 风险 2）；满意度 < 3.5 或多数人选竞品 → 先改排版引擎，不加新功能。

## 11. 三个问题的回答

1. **为什么一个不擅长做手账的美国用户会选 Little Days？** 因为她已经每天在拍照，却没时间、也不会把它们做成好看的东西。Little Days 让她只做一件事——选今天的照片、最多写一句——就得到一套像手做的手账页，而且这些页会自己变成一本书。（这是假设，要用 §10 验证。）
2. **应该在哪个具体体验上明显比竞品好？** **「从今天的相册到一套满意的手账页」这 60–90 秒**：自动按时间分成几个 Moment、封面 + 章节有层次、整套配色字体统一、默认不裁切、改了也不会被重排冲掉。Zinnia 要手做，Day One 和 Apple Journal 是信息流，Layout / Shuffles 只给一张拼图。
3. **如果下一轮只能做三个功能？**
   1. 多 Moment 的 Quick Create（选照片 → 自动分组 → 一句话 → 保存进书）。
   2. 排版引擎 v2（7 个模板规则 + 主题套装 + 文字适配 + 装饰空位）。
   3. 自动与手动共存（钉住手动调整 + 草稿恢复）。
