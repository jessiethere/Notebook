## 1. Current Quick Create Flow Audit

路径：首页「选照片」→ 系统选择器 →「今天的故事」→ 风格（杂志 / 手账 / 拼贴）、重新排版、写一句、调整分组、自定义 → 保存 → 阅读器。

| 问题 | 根因（代码核对） |
|---|---|
| A 换照片不直观 | 「今天的故事」里**没有替换照片**。点照片只会打开「写一句」或放大；替换只在「自定义」（完整编辑器）里有，要先选中照片才出现「替换」。从「自定义」回来后，故事页的「写一句」入口和编辑器的文字工具是两套东西，所以找不到之前的入口。 |
| B 双照片默认排版不稳 | `scrapbook-layout.mjs` 杂志风格两张照片时（`n === 2 && heroAtTop && textUnits(title) <= 24`）会把第二张缩小放到右边，**左边留一栏给「那句话」**。没写字时这一栏空着，就成了「一大一小 + 大片空白」。截图和 Mac WebKit 里都复现了。 |
| C 「未命名的一页」 | 约 20 处用 `title || t("moment.untitled")` / `t("entry.untitled")` 作为后备显示；Captain 的整理还提醒「有 N 页还没有名字」。**已在 V10.27 修复**，见第 2、3 节。 |
| Reader 蓝框 | 不是编辑选中态：Reader 的照片带 `tabindex="0"`（可以放大），键盘焦点落到照片上时 WebKit 画系统默认的**蓝色焦点框**。Mac WebKit 里复现。**已在 V10.27 修复**。 |

其它：「写一句」被底部按钮条挡住、输入框不自动聚焦、书和日期是两个原生下拉框（见 `CORE_FLOW_AUDIT.md`）。

## 3. Optional Title 的统一展示规则（已实施）

1. 用户写的标题，原样显示。
2. 用户自己的一小段文字：正文或文字图层；不取标题绑定的字、不取跨页副本；最多 18 个字，加「…」。
3. 页面上实际有的东西：`2 张照片 · 1 段视频` / `2 photos · 1 video`（单复数分开）。
4. 记录的时间段：`晨间记录 / 午后记录 / 傍晚记录 / 晚间记录`（Morning / Afternoon / Evening / Night notes），按页面时间算。
5. `第 N 页`，或「一页记录」。

另外：

- 列表里在前面加时间：`11:05 · 2 张照片`。一整天的卡片用 `dayLabel`：标题 → 第一页的标题 → 第一段文字 → `3 页 · 6 张照片` →「这一天」。
- 展示名**只用于显示，从不写进 `title`**。补上标题后各处显示标题；删掉标题后恢复展示名。页面、照片和文字都不动。
- 旧页面不需要迁移；数据库里空的 title 保持为空。
- `moment.untitled`、`entry.untitled`、`kp.untitled`、`kp.org.untitled` 这四个文案已经删除。单元测试检查所有展示名文案里没有「未命名 / 无标题 / Untitled」。

| 状态 | 内容 |
|---|---|
| 默认 | 顶部一行「11月13日 · 平凡日子里的小确幸 ›」（点了再改书和日期）；右上角「自定义」；页面；底部三个按钮〔换照片〕〔写文字〕〔换个排版〕+〔保存〕 |
| 换照片 · 选哪一张 | 面板显示这一页照片的真实缩略图（第 1 张 / 第 2 张）。点页面上的照片或缩略图都能选，被选中的那张在页面上描边并标「第 2 张」。说明「文字、字体和版式会保留；新照片比例不同时会重新排这一页，可以撤销」。按钮〔取消〕〔替换这张照片〕 |
| 换照片 · 替换后 | 页面直接更新，提示「已换成新照片 · 第 2 张的文字保留了 · 撤销」 |
| 写文字 | 沿用现有面板（整体 / 每张照片的真实缩略图）；**打开就聚焦输入框**；字体、字号、粗体、颜色、对齐收进「字体与样式 ›」；提示「可以不写，直接保存」 |
| 写文字 · 字体与样式 | 展开后就是现有的这些控件 |
| 换个排版 | 3 个缩略图（推荐 · 当前 / 并排 / 错落）；照片和文字都保留 |

数据规则：

- 替换照片：只改那张照片图层的 `mediaRef` 和比例。图层 `id` 不变，所以它的文字（`caption`，按照片图层 id 关联）跟着位置走。如果比例变了，只重新排这一页，用同一个风格和版式编号。
- 文字和字体：整体那句话存在 `moment.title`，每张照片的文字存在照片图层的 `caption`，字体样式存在 `moment.typeStyle`。换排版时这些都不动。
- 不另写画布引擎：替换复用编辑器已有的替换和保存（字节存储 + 读回校验）；排版复用 `layoutMoment`。

## 5. 双照片自动排版（V10.28 已实施，2026-11-13）

> 用户确认后已实施：见 `scrapbook-layout.mjs` 的 `pairLayout`，测试 `tests/v128.test.mjs`、`tests/v128-browser.cjs`。实施时多做了一点：两张形状差很多时，小的那张在共同边上放大到一半差距，让两张更均衡。

算法：没写字的两张照片当作「一对」处理。同时算三种排法：

- 并排同高；
- 上下同宽；
- 错落（并排、第二张下移约三分之一）。

用三个指标打分：照片占版面的比例 × 两张大小是否均衡 × 横向是否占满。两张面积差太多（小于 0.35）时打对折。默认用得分最高的；「换个排版」依次换成第二、第三高的。最后整体垂直居中，算高度时不把页脚那行字算进去。照片不裁切，图片里自带的文字（截图、表情图）完整保留。写了一句话的情况仍用现有的「照片 + 旁边一栏文字」版式。

测试素材：用仓库照片做成手机常见比例，4:3、3:4、16:9、1:1，以及一张 9:16、上下带字的截图式图片。共 6 组：横 + 横、横 + 竖、竖 + 竖、16:9 + 9:16（带字）、方 + 竖、竖 + 横。

回归中发现并修复（V10.30，只影响新排版的页面）：

- 杂志风格**两张照片配一段长文字**（超过约 24 个汉字宽）时，第二张会被挤得很小（宽约 11%）。现在也用并排 / 上下 / 错落，文字放在照片下面。
- 杂志风格**很多张照片配一段长文字**时，大照片下面的照片会缩成邮票大小（最窄约 3%）。现在只要有一张不到页面宽的 14%，就把所有照片排成整齐的几行。

仍然存在、没有修的：

- 9:16 的竖图和三张其他照片配长文字时，那张竖图宽约 11%（高约 16%），能看清，但偏小；
- 五张竖图配短文字并且每张都写了字时，有一行字压到照片约 10%；
- 三张照片配长文字时，下面两张偏小，但都超过最小尺寸。

计时（Chromium，本机容器，没有其他任务时）：从选好照片到排好的页面出现，1 张约 0.1 秒，5 张约 0.3 秒。脚本跑完 Flow B → F → C 约 3 秒，这不是人的操作时间。
